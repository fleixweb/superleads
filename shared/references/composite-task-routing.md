# 组合任务路由规则

同一次请求包含两个或以上明确业务目标时，建立一个父级组合任务，不得要求用户为了内部架构而拆成多次调用。先提取共享的公司/域名/地址、产品、目标国家、客户类型、资料范围和输出要求，再为每个明确目标建立独立子任务：客户背调、产品市场分析、批量客户发现、表格补全、公开联系人补充或最终导出。

只有存在真实数据依赖时才串行。独立查询组、来源打开、候选联系人补充和资料整理可以并行规划；同一主体的身份合并、冲突处理、证据升级、最终审核、正式导出和组合报告汇总必须串行。没有宿主并行或后台能力时，必须说“分批执行”，不得伪造实时并行。

每个子任务独立记录用途、来源、事实域、已确认项、待确认项、来源受限和本轮未执行项。不得让一个子任务的来源自动升级为另一个子任务的事实：公司来源不证明产品准入，法规来源不证明客户身份或采购意向，搜索摘要不成为事实。

一个子任务缺少必要输入、能力不可用或来源受限时，只标记该子任务等待/部分完成/来源受限；其他独立子任务仍可交付。父报告按子任务分节，不能输出客户价值、采购意向或市场进入建议。
