# Superleads plugin distribution UAT — 2026-08-02

## Scope

This UAT covers only the plugin publication / installation chain for the product outbound market analysis route. It does not change the product-market analysis rules or report-writing constraints.

## Findings

1. The active Codex install is `superleads@fleix` from the local personal marketplace at `/home/fleix/.agents/plugins/marketplace.json`.
2. That marketplace points to `/home/fleix/plugins/superleads`, which is a symlink to `/home/fleix/superleads`.
3. `codex plugin add superleads@fleix` writes the runtime cache under `/home/fleix/.codex/plugins/cache/fleix/superleads/<version>/`.
4. The optional `hooks/` files only perform a silent update notice. They do not copy, install, or update plugin cache contents.
5. The stale `0.1.3` cache was created from commit `40c91c5` on 2026-07-20. That commit has 12 skill directories and no `spec/` tree. The product-market Skill and intake reference were added later, starting at `8462628` on 2026-07-27, while the plugin version remained `0.1.3`.
6. The local Codex installer snapshots the plugin source tree, not just the `skills` manifest path. Therefore `shared/` existed in `0.1.3` because it existed in the 2026-07-20 source tree, while `spec/` did not exist because it was not yet in that source tree. The new `0.1.4` cache contains both `shared/` and `spec/`.

## Root cause

The release version stayed at `0.1.3` after new runtime files were added. Existing Codex sessions kept loading the stale `0.1.3` cache, so `skills/analyzing-product-outbound-market/`, `shared/references/product-outbound-market-intake.md`, and all referenced `spec/` files were absent from runtime.

The fix is to publish/install a new plugin version (`0.1.4`) and add an install-integrity gate that fails if the runtime cache or materialized package is missing skills or has dead `../../spec/` / `../../shared/` references from `SKILL.md` files.
