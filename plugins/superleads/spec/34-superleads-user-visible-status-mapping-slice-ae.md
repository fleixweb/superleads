# Slice AE：状态词压缩与用户可见状态映射

日期：2026-07-29

## 1. 本 Slice 要解决什么

前序 Slice AA/AB/AC/AD 已经把 Superleads 往“弱证据收敛 + 可审计交付”方向校准：

- 弱来源不能升级为强事实；
- 多个弱来源一致可以表达为收敛线索，但不能替代官方/主管来源；
- 法规、关税、认证、COO、物流和近期因素必须考虑资料时效；
- 权威来源要按来源身份、事实域、管辖范围、证据和时效核验，不能靠国家清单、域名或关键词。

这些机制让内部判断更安全，但也带来一个新问题：内部状态枚举变多，用户如果直接看到 `verified / candidate / unable_to_verify / stale_needs_recheck / secondary_reference_only / conflict_present` 等状态，会觉得这是机器工作流，不是外贸业务报告。

本 Slice 冻结一个展示层原则：

> 内部状态可以细，用户可见状态必须少、稳、人话，并且把“业务结论”和“依据状态”分开。

本 Slice 不写代码、不新增真实来源、不修改法规、关税或市场事实；只冻结未来 Code Slice AE 的输出合同和映射规则。

## 2. 一句话原则

**用户不是要看系统状态机，用户要知道：这条信息现在能不能用、还能差什么、不能推出什么。**

因此所有三条路线都应尽量使用以下人话结构：

| 用户问题 | 对应展示字段 |
|---|---|
| 现在看到什么？ | `当前判断` / `当前看到的业务信号` |
| 这条信息靠谱吗？ | `依据状态` |
| 为什么是这个状态？ | `依据说明` |
| 下一步找谁确认？ | `下一步确认对象` |
| 不能把它当成什么？ | `不能推出什么` |

## 3. 核心纠偏：结论状态 ≠ 证据状态 ≠ 用户材料状态

产品出海市场分析中最容易混淆三类状态：

| 类型 | 回答的问题 | 例子 | 不能混用成什么 |
|---|---|---|---|
| 业务/规则结论 | 目标市场规则可能怎么要求 | `通常需要 COO`、`满足优惠税率条件时需要 proof of origin`、`未能核实目标国规则` | 不能由用户有没有文件反推 |
| 依据状态 | 支撑这条结论的来源强度、时效和边界 | `已有明确依据`、`需权威/专业复核`、`资料过旧需复核` | 不能写成产品已合规或最终税费 |
| 用户材料状态 | 用户当前有没有对应材料、材料是否覆盖本场景 | `用户已提供，需核对范围`、`当前未见用户材料` | 不能替代目标国规则判断 |

示例：

| 错误表达 | 正确表达 |
|---|---|
| 用户没提供 COO，所以无法分析是否需要 COO | 目标国规则：本轮未能核实；用户材料：当前未见；下一步：查目的国海关/协定规则 |
| 用户提供 UN38.3，所以美国锂电合规 | 用户材料：已提供测试文件线索，需核对型号/版本/日期/签发机构；目标国/运输要求仍需按承运和法规复核 |
| 认证机构页面写了某标准，所以目标国强制认证 | 当前判断：认证路径线索；依据状态：需权威/专业复核；不能推出：法律强制或产品已合规 |

## 4. 用户可见状态词首版压缩为 11 个

### 4.1 统一状态词

这 11 个状态是用户可见层的主状态。内部仍可保留更细枚举，但导出 Markdown / CSV / Excel 时优先投影为这些状态。

| 用户可见状态 | 人话解释 | 能支持什么 | 不能支持什么 |
|---|---|---|---|
| 已有明确依据 | 已打开并记录来源，来源与字段范围匹配，且没有明显时效/权威性问题 | 支持当前字段本身 | 不支持最终裁定、商业推荐、采购概率、是否值得进入 |
| 按已知数据计算 | 用已核实数字按明示公式计算 | 支持该公式结果 | 不替代原始测试报告、官方归类、最终税额 |
| 多来源方向一致 | 多个独立弱来源指向同一方向 | 支持“线索收敛” | 不等于官方确认、最终事实、强制要求 |
| 可作为线索 | 有公开信号或参考来源，但口径有限 | 支持下一步查询方向 | 不支持确定性法规、税费、认证、销量、采购意愿 |
| 需补充资料 | 缺用户产品参数、订单信息、技术文件、实物照片或供应链文件 | 支持列出待补材料 | 不支持直接判断符合/不符合 |
| 需权威/专业复核 | 当前结论需要主管机关、报关行、认证机构、承运人、律师或进口商确认 | 支持提示复核路径 | 不支持写成已合规、无需许可、最终税率 |
| 资料过旧需复核 | 来源日期过旧、日期未知或超过本事实域复核窗口 | 支持历史参考和复核提醒 | 不支持“最新”“现行”“当前有效” |
| 来源受限 | 来源未打开、付费墙、摘要页、登录墙或只能看到片段 | 支持说明存在来源线索 | 不支持把摘要写成事实 |
| 说法冲突待复核 | 不同来源、不同口径或不同日期指向冲突 | 支持提醒人工复核 | 不支持选择其中一边当结论 |
| 本轮未执行 | 本次没有采集或没有运行该模块 | 支持说明未覆盖范围 | 不支持补样板事实或行业常识 |
| 暂不适用 | 按当前产品档案/贸易路径暂未触发该项 | 支持当前场景排除说明 | 不支持泛化到其它型号、用途、国家或交易条件 |

### 4.2 不再新增用户可见状态的原则

新增内部枚举时，不自动新增用户状态。只有满足以下条件，才允许新增用户可见状态：

1. 外贸业务人员能凭这个状态做不同动作；
2. 现有 11 个状态无法表达；
3. 三条路线至少两条路线可能复用，或产品市场分析里多个模块复用；
4. 能写出明确的 `不能支持什么`；
5. 有静态 eval 防止误用。

## 5. 内部状态到用户可见状态的映射

### 5.1 产品市场分析通用 `Status`

| 内部状态 | 用户可见状态 | 展示补充 |
|---|---|---|
| `verified` | 已有明确依据 | 仅当无 stale、authority mismatch、conflict 等降级信号 |
| `derived_calculation` | 按已知数据计算 | 必须显示公式和原始字段来源 |
| `candidate` | 可作为线索 | 可进入下一步核验，不是结论 |
| `preliminary_reference` | 可作为线索 | 如有多来源互证，可另加“多来源方向一致”标签 |
| `business_confirmation_required` | 需补充资料 | `下一步确认对象` 写用户、进口商、供应链、订单文件等 |
| `technical_docs_required` | 需补充资料 | `下一步确认对象` 写制造商、SDS、UN38.3、BOM、标签、规格书等 |
| `physical_verification_required` | 需补充资料 | `下一步确认对象` 写实物照片、样品、标签、水洗标等 |
| `professional_confirmation_required` | 需权威/专业复核 | 写明报关、认证、承运、法律、主管机关等对象 |
| `source_restricted` | 来源受限 | 不能把摘要、搜索结果或付费墙标题升级为事实 |
| `not_executed` | 本轮未执行 | 短句显示，不补模板行制造事实 |
| `not_applicable` | 暂不适用 | 说明当前场景为什么暂未触发 |
| `not_provided` | 需补充资料 | 用缺口说明解释缺什么，不能留空 |
| `conflict_pending_review` | 说法冲突待复核 | 必须保留冲突双方或冲突口径 |

### 5.2 多来源互证状态

| 内部状态 | 用户可见状态 | 边界 |
|---|---|---|
| `multi_source_consistent` | 多来源方向一致 | 只能说明多个弱来源方向一致，不能升级为官方确认 |
| `single_source_only` | 可作为线索 | 单来源线索 |
| `not_enough_independent_sources` | 可作为线索 | 独立性不足，不能写“多来源” |
| `conflict_present` | 说法冲突待复核 | 冲突优先显示 |
| `source_restricted` | 来源受限 | 来源打不开或只有摘要 |
| `not_executed` | 本轮未执行 | 未做互证 |

### 5.3 资料时效状态

| 内部状态 | 用户可见状态 | 展示方式 |
|---|---|---|
| `current_enough_for_scope` | 已有明确依据 | 同时展示来源日期/观察日期 |
| `date_unknown_recently_observed` | 需权威/专业复核 | 观察日期不是来源日期；不写最新 |
| `stale_needs_recheck` | 资料过旧需复核 | 覆盖原本的“已核实”主状态 |
| `date_unknown_needs_recheck` | 资料过旧需复核 | 日期未知且事实域敏感 |
| `not_time_sensitive` | 已有明确依据 / 可作为线索 | 取决于基础来源强度 |
| `not_executed` | 本轮未执行 | 未做 freshness 判断 |

### 5.4 来源权威性状态

| 内部状态 | 用户可见状态 | 展示方式 |
|---|---|---|
| `verified_for_fact_domain` | 已有明确依据 | 只限该事实域、该国家/地区、该适用条件 |
| `candidate_needs_check` | 可作为线索 | 来源身份或范围待核实 |
| `secondary_reference_only` | 可作为线索 / 需权威/专业复核 | 辅助解释，不支撑强监管结论 |
| `unable_to_verify` | 需权威/专业复核 | 保留官方核实路径 |
| `conflicting_identity` | 说法冲突待复核 | 来源身份冲突优先显示 |
| `not_executed` | 本轮未执行 | 未做权威性核实 |

### 5.5 COO / 原产地证明规则结论

这组不是证据状态，必须作为 `目标国规则结论` 展示。

| 内部状态 | 用户可见规则结论 | 依据状态如何配合 |
|---|---|---|
| `required` | 目标国规则显示通常需要 | 仍需显示依据状态和适用条件 |
| `conditionally_required` | 满足条件时需要 | 必须列触发条件，如优惠税率、FTA、配额、进口商/信用证要求等 |
| `normally_not_required` | 当前场景通常不要求 | 只能在有权威依据时显示为明确结论 |
| `not_applicable` | 本场景暂不适用 | 不泛化到其它贸易路径 |
| `unable_to_verify` | 本轮未能核实目标国规则 | 不能由用户材料状态替代 |

### 5.6 认证 / 目的国准入规则结论

这组也不是证据状态，必须作为 `目标国准入要求结论` 展示。

| 内部状态 | 用户可见规则结论 | 依据状态如何配合 |
|---|---|---|
| `required` | 目标市场规则显示通常要求 | 需要事实域匹配的官方/权威来源 |
| `conditionally_required` | 满足条件时要求 | 必须列产品属性、用途、渠道、年龄段、材质、带电/危险品等触发条件 |
| `normally_not_required` | 当前场景通常不要求 | 只能在权威来源覆盖当前条件时显示 |
| `not_applicable` | 本场景暂不适用 | 不泛化到其它型号、用途或销售渠道 |
| `unable_to_verify` | 本轮未能核实目标市场规则 | 不能写成不需要 |
| `not_executed` | 本轮未核验此项 | 简短说明未执行，不补模板事实 |

### 5.7 用户材料状态

用户材料状态必须与目标国规则结论分列。

| 内部状态 | 用户可见材料状态 | 禁止推导 |
|---|---|---|
| `user_material_not_requested_yet` | 尚未向用户索取 | 不代表没有材料 |
| `user_material_status_unknown` | 用户材料状态未知 | 不代表不需要 |
| `user_not_provided_but_required` | 当前未见用户材料，规则可能要求 | 不代表不能做，只提示缺口 |
| `user_not_provided_and_not_required_for_current_scenario` | 当前未见用户材料，且本场景暂未触发要求 | 不泛化到其它场景 |
| `user_provided_needs_review` | 用户已提供，需核对范围 | 不代表目标国认可 |
| `user_provided_valid_for_scope` | 用户已提供，范围初步匹配 | 不代表海关/平台/认证机构最终接受 |
| `user_provided_not_valid_for_scope` | 用户已提供，但与本场景不匹配 | 不代表产品本身不能出口 |

## 6. 状态投影优先级

当一行同时有多个内部状态时，用户可见 `依据状态` 按以下优先级投影，避免“已核实但过期”“已核实但权威性不匹配”这类误导。

| 优先级 | 触发条件 | 用户可见状态 | 原因 |
|---:|---|---|---|
| 1 | 该模块未执行 | 本轮未执行 | 未执行不能显示事实行 |
| 2 | 当前场景明确不适用 | 暂不适用 | 不适用是一种场景说明 |
| 3 | 来源或结论冲突 | 说法冲突待复核 | 冲突不能被其它状态覆盖 |
| 4 | 来源打不开、付费墙、摘要、登录限制 | 来源受限 | 来源受限不能升级事实 |
| 5 | freshness 过旧或日期未知需复核 | 资料过旧需复核 | 时效风险必须压过“已打开” |
| 6 | 强监管事实域缺权威核实 | 需权威/专业复核 | 认证、关税、COO、出口管制等不能弱来源升级 |
| 7 | 缺产品/订单/技术/实物/供应链材料 | 需补充资料 | 用户下一步可行动 |
| 8 | 已核实数字公式计算 | 按已知数据计算 | 公式结果单独显示 |
| 9 | verified 且没有降级信号 | 已有明确依据 | 支持当前字段本身 |
| 10 | 多个独立弱来源一致 | 多来源方向一致 | 提升线索层次但不升级事实 |
| 11 | 候选、初步参考、单一弱来源 | 可作为线索 | 默认弱证据状态 |

说明：`目标国规则结论`、`目标国准入要求结论`、`用户材料状态` 不参与这个优先级，它们是独立字段；优先级只用于 `依据状态`。

## 7. 三条路线如何使用这套状态

### 7.1 批量客户开发

批量客户开发不应该展示“推荐客户 / 采购概率 / 最佳客户”。

建议保留两个字段：

| 字段 | 允许值 / 写法 |
|---|---|
| `相关性状态` | `直接相关`、`可能相关`、`边界线索`、`信息不足`、`身份待确认`、`已排除` |
| `依据状态` | 使用本 Slice 11 个统一状态词 |

示例：

| 候选客户 | 当前看到的业务信号 | 相关性状态 | 依据状态 | 还要确认什么 |
|---|---|---|---|---|
| 示例经销商 A | 官网目录出现 diesel generator parts，地区为美国 | 可能相关 | 可作为线索 | 是否做进口采购、是否接受海外供应商 |
| 示例维修链 B | 多个页面指向 generator repair / parts | 直接相关 | 多来源方向一致 | 采购主体和公开联系入口 |

### 7.2 单一客户背调

单客背调用户最关心“这个对象是谁、和我有什么关系、能不能联系”。

建议字段：

| 字段 | 说明 |
|---|---|
| `当前判断` | 公司/品牌/域名/主体关系的人话说明 |
| `依据状态` | 使用本 Slice 11 个统一状态词 |
| `主体边界` | 哪些能确定，哪些只是同名/关联线索 |
| `不能推出什么` | 不推出采购负责人、采购意愿、采购概率 |

示例：

| 问题 | 当前判断 | 依据状态 | 不能推出什么 |
|---|---|---|---|
| 这个网站对应谁 | 官网页脚和联系页指向同一经营主体 | 已有明确依据 | 不代表其有当前采购计划 |
| Founder 是不是采购负责人 | 公开资料只显示人员身份 | 可作为线索 | 不能写成采购负责人 |

### 7.3 产品出海市场分析

产品市场分析必须把 `当前判断`、`规则结论`、`用户材料状态`、`依据状态` 分开。

示例字段：

| 字段 | 用途 |
|---|---|
| `模块` | 趋势、价格、认证、COO、税费、物流等 |
| `当前判断` | 人话摘要 |
| `目标国规则结论` | 只在 COO / 认证 / 准入 / 税费等适用模块出现 |
| `用户材料状态` | 只在证书、测试报告、COO、SDS、标签等适用模块出现 |
| `依据状态` | 使用本 Slice 11 个统一状态词 |
| `下一步确认对象` | 用户、制造商、进口商、报关行、承运人、认证机构、主管机关等 |
| `不能推出什么` | 防止弱证据升级 |

示例：

| 模块 | 当前判断 | 目标国规则结论 | 用户材料状态 | 依据状态 | 下一步确认对象 | 不能推出什么 |
|---|---|---|---|---|---|---|
| 原产地证明 / COO | 需要查目的国是否要求 proof of origin | 本轮未能核实目标国规则 | 当前未见用户材料 | 需权威/专业复核 | 目的国海关 / 进口商 / 报关行 | 不能由 Made in 或用户没给证书推出需要/不需要 |
| 锂电运输文件 | 960Wh 锂电池包会触发危险品运输核验 | 满足条件时要求 | SDS / UN38.3 当前未见 | 需补充资料 | 制造商 / 承运人 / 货代 | 不能写成可出运或已合规 |
| 平台价格 | 已看到相近规格线上挂牌价 | 不适用 | 不适用 | 可作为线索 | 用户自行比较规格 | 不等于成交价、批发价或推荐报价 |

## 8. Markdown / CSV / Excel 展示合同

### 8.1 推荐表头

产品市场分析用户可见主表推荐表头：

| 字段名 | 是否必须 | 说明 |
|---|---|---|
| `模块` | 是 | 趋势、价格、准入、税费、COO、物流等 |
| `项目` | 是 | 具体信息项 |
| `当前判断` | 是 | 人话，不写内部 enum |
| `规则结论` | 条件必填 | 认证、COO、税费、出口要求等规则类项目必填 |
| `用户材料状态` | 条件必填 | 用户证书、SDS、COO、标签、BOM、测试报告等材料类项目必填 |
| `依据状态` | 是 | 使用本 Slice 11 个状态词 |
| `依据说明` | 是 | 简短说明为什么是这个状态 |
| `下一步确认对象` | 是 | 用户、制造商、进口商、报关行、认证机构、承运人、主管机关等 |
| `不能推出什么` | 是 | 明确边界，防止价值判断和证据升级 |
| `来源 / 日期` | 是 | 来源名、URL/文件、来源日期/观察日期/日期未见 |

批量客户开发和单一客户背调可复用 `依据状态 / 依据说明 / 不能推出什么`，但不强制出现 `规则结论 / 用户材料状态`。

### 8.2 未执行模块展示

未执行模块必须简短显示，不能为通过校验补事实样板。

推荐写法：

| 模块 | 依据状态 | 说明 |
|---|---|---|
| Google Trends | 本轮未执行 | 未采集相对搜索兴趣数据 |
| 国际快递 | 本轮未执行 | 未按包裹尺寸、重量、带电/液体/磁性等条件核验快递规则 |

禁止写法：

| 禁止写法 | 原因 |
|---|---|
| 自动补一行“国际快递：待确认，常见 3-7 天” | 未采集就不能补行业常识 |
| 未执行模块完全不展示 | 用户会误以为已覆盖 |
| 把未执行写成“不适用” | 未执行和不适用不是一回事 |

## 9. Code Slice AE 最小实现边界

Code Slice AE 应只做“状态投影与用户展示合同”，不重构业务事实图谱。

| 模块 | 最小实现 |
|---|---|
| 状态映射工具 | 新增或集中一个内部状态 → 用户可见状态的纯映射函数/表 |
| 导出器 | Markdown / CSV / Excel 统一使用人话状态；不暴露内部 enum |
| 用户可见 validator | 检查导出中不能出现内部状态词、不能缺少依据状态、不能把过旧/来源受限/权威未核实显示成已明确 |
| fixtures/evals | 增加 pass/fail：stale 覆盖 verified、authority mismatch 降级、COO 规则与用户材料分列、未执行不注水、Google Trends 不写销量 |
| 文档 | 更新 `shared/references/status-labels.md` 或新增 status projection reference，供三路线复用 |

不做：

- 不删除底层 schema 里的内部枚举；
- 不新增真实搜索；
- 不改 Source Pack 事实；
- 不把状态词压缩成二值；
- 不把“需复核”变成“不能做业务”；
- 不把“多来源方向一致”升级为“已核实”。

## 10. 验收样例

| 样例 | 输入状态 | 期望用户可见 |
|---|---|---|
| 旧官方税则 | `verified` + `stale_needs_recheck` | `资料过旧需复核`，不能写最新税率 |
| 第三方货代博客说认证 required | `secondary_reference_only` / `candidate` | `可作为线索` 或 `需权威/专业复核`，不能写目标国强制要求 |
| 多个平台同类产品都在卖 | `multi_source_consistent` | `多来源方向一致`，但不能写销量好或值得进入 |
| 用户没给 COO | `user_material_status_unknown` + 目标国规则未核实 | 规则结论写未能核实；用户材料写未知/未见；不能互相推导 |
| 未采集 Google Trends | `not_executed` | `本轮未执行`，不能补趋势判断 |
| 产品属性显示液体但未核验快递 | `technical_docs_required` / `not_executed` | `需补充资料` 或 `本轮未执行`，不能写可走国际快递 |
| 背调中找到 Founder | `preliminary_reference` | `可作为线索`，不能写采购负责人 |
| bulk 中候选经销商只有目录线索 | `possibly_related` + `single_source_only` | 相关性可能相关，依据状态可作为线索，不写推荐客户 |

## 11. 非目标

- 不判断产品是否值得进入目标国家/地区；
- 不推荐客户、不排序、不写采购概率；
- 不给推荐报价、目标价格或最佳物流路线；
- 不把旧资料、摘要、搜索结果、平台价格、Google Trends、候选 HS、用户材料或多弱来源升级成最终事实；
- 不把状态压缩成“能/不能”二元结论；
- 不为所有国家/地区预置状态或权威机构。

## 12. 决策

从 Slice AE 起，Superleads 的用户可见交付层采用“双层表达”：

1. `当前判断 / 规则结论 / 用户材料状态` 回答业务问题；
2. `依据状态 / 依据说明 / 不能推出什么` 回答证据边界。

内部状态枚举继续服务 validator、audit、skill handoff 和 eval；用户可见层统一投影为 11 个状态词，减少状态词通胀，同时保留弱证据外贸场景所需的中间层。
