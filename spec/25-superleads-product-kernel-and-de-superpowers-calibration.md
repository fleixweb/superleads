# Slice R：Superleads 产品内核复盘与去 Superpowers 化校准

日期：2026-07-27

## 1. 这次复盘要解决什么

用户提出的担心是合理的：Superleads 在执行方式上大量借鉴了 Superpowers 的计划、切片、验证、交接、eval 思路；如果不校准，产品会滑向“一个证据工作流框架”，而不是“外贸人能用的客户开发与市场分析工具”。

本 Slice R 的结论：

> Superpowers 可以作为 Superleads 的工程执行纪律参考，但不能成为 Superleads 的产品本体、用户语言或业务世界模型。

Superleads 的产品本体必须来自真实国际贸易业务：

- 卖什么；
- 卖往哪里；
- 找谁买；
- 这个对象是否真实相关；
- 产品进入目标市场有哪些客观条件；
- 哪些信息已经有来源，哪些只是线索、候选、受限或待确认。

## 2. 当前产品类型与阶段

| 项目 | 当前判断 |
|---|---|
| 产品类型 | Mixed：Agent / CLI / 导出文件 / Skill Suite |
| 主入口 | Agent 对话入口；CLI 与脚本是可验证执行层 |
| 当前阶段 | WOBSE 中的 Spec / Execute 之间，需要回到 Why / Bet 做一次校准 |
| 本轮任务 | 产品内核复盘，不写功能代码 |
| 本轮输出 | 冻结 Superleads 与 Superpowers 的关系、Superleads 自有产品原则、过度工程化风险和下一步判断门槛 |

## 3. Superleads 的一句话定义

Superleads 是面向国际贸易场景的公开信息研究与交付系统，帮助用户围绕“客户开发、客户背调、产品出海市场分析”整理可追溯、可复核、可导出的业务情报。

它不是：

- 通用 Agent 工作流框架；
- 软件开发方法论工具；
- 自动给商业建议的咨询顾问；
- 自动推荐客户或市场的黑箱模型；
- 自动判断法律、税率、认证、物流可行性的权威系统。

## 4. Superleads 的三条产品路线

| 路线 | 用户真正要做的事 | Superleads 的交付 | 不做什么 |
|---|---|---|---|
| 批量客户开发 | 我卖某类产品，想找一批海外潜在客户 | 候选客户池、公开信号、联系人入口、相关性状态、导出表 | 不替用户定义 ICP，不默认筛剩“推荐客户”，不把弱证据删除 |
| 单一客户背调 | 我有一个公司/品牌/域名/邮箱，想知道它是谁、是否相关、有什么公开线索 | 单客背景报告、身份关系、公开业务信号、联系入口、待确认项 | 不扩展成批量找客户，不把同名公司混为一个主体 |
| 产品出海市场分析 | 我有一个产品，想知道进入/销售到某目标国家有哪些市场、准入、税费、出口、物流客观条件 | 产品市场与准入信息矩阵、来源与待确认事项、CSV/Markdown 导出 | 不生成客户名单，不判断值不值得进入，不推荐报价或最佳路线 |

这三条路线是 Superleads 的业务内核。所有流程、schema、skill、eval 都必须服务这三类真实外贸动作，而不是服务抽象工作流美感。

## 5. 哪些东西可以继续参考 Superpowers

Superpowers 的价值在于执行纪律，而不是外贸产品知识。

| 可参考部分 | 在 Superleads 中的合理用法 | 边界 |
|---|---|---|
| Plan / Execute / Verify | 把外贸研究拆成范围、计划、采集、验证、导出 | 不把 plan 当用户价值本身 |
| 小切片推进 | Code Slice A-M 这种可验证增量 | 切片不能无限替代真实业务样本运行 |
| Handoff / TASKS | 保证长会话和个人开发可接续 | 不在用户交付里暴露内部交接语言 |
| Eval / fixtures | 把常见外贸误导做成可回归测试 | eval 必须对应真实业务错误，不是为了测试而测试 |
| Verification before completion | 交付前防止幻觉、路径泄露、事实升级 | 不能把所有弱证据都判成失败；弱证据应降级显示 |
| Review / remediation | 冲突、缺口、误导性升级时打回 | 不把每个普通用户请求都变成复杂审计流程 |

## 6. 哪些东西不能照搬 Superpowers

| 不能照搬的点 | 为什么 | Superleads 的替代原则 |
|---|---|---|
| 把执行阶段当产品主线 | 用户关心客户、公司、产品、国家、税费、物流，不关心 workflow stage | 用户可见主线必须是外贸业务对象 |
| 把所有任务都变成 formal review / audit | 外贸公开信息天然弱证据，过严会让工具无法产出候选池 | 弱证据保留但降级；误导性结论才阻断 |
| 把内部对象名暴露给用户 | Claim、EvidenceCard、MatrixRow、SearchLog 不是人话 | 用户看“来源、依据、还缺什么、不能推出什么” |
| 为了框架完整而新增层级 | 层级越多，越可能偏离真实业务动作 | 每新增对象必须回答：用户交付中减少了哪类误导？ |
| 把测试覆盖率当产品进展 | `670/670` 只说明已知边界没破，不说明外贸人觉得好用 | 必须用真实业务样本和用户可见报告验收 |
| 把“严格”误解为“只给确定事实” | 外贸研究里很多有价值信息是候选、线索、待确认 | 用状态词表达不确定，不强行删掉 |

## 7. Superleads 自己的第一性原则

### 7.1 先服务外贸业务动作

每个功能必须能落到一个真实动作：

- 找客户；
- 查客户；
- 分析产品进入目标市场的客观条件；
- 整理公开联系入口；
- 把用户材料转成可复核业务资料；
- 导出销售能看懂、能继续跟进的表格。

如果一个功能只能解释为“让内部图谱更完整”，但不能改善上述动作，应进入停车场。

### 7.2 证据链是手段，不是产品本身

Superleads 要做证据链，是因为外贸场景高频出现：

- 公司同名；
- 品牌、网站、运营主体、进口商、经销商混杂；
- 搜索摘要诱导错误；
- 平台价格不是成交价；
- 公开页面不是实物标签；
- 工厂地址不是起运港；
- 候选税号不是最终税率；
- 用户有/没有 COO 不等于目标国是否要求 COO。

证据链的目标是防止这些错误，不是让系统看起来像一个通用审计平台。

### 7.3 弱证据不删除，误导性升级才阻断

Superleads 不应该把弱证据简单判为失败。真实外贸业务中，很多公开线索有用但不确定。

| 情况 | 应该怎么处理 |
|---|---|
| 搜索摘要显示可能相关 | 作为候选线索，不成事实 |
| 公开页面能看到产品关键词 | 可作为初步相关信号 |
| 来源受限 / 登录墙 / PDF 未打开 | 显示来源受限或需复核 |
| 公司身份冲突 | 保留冲突，不能强行合并 |
| 候选客户只有部分相关信号 | 降级为可能相关或待确认 |
| 用户要求最终税率/合规结论但前提不足 | 阻断确定结论，列待确认项 |

### 7.4 用户可见语言必须是外贸人话

内部可以有 `SearchLog`、`Observation`、`EvidenceCard`、`MatrixRow`，但用户应看到：

- 我理解你卖的是；
- 本次优先找；
- 本次不纳入；
- 判断依据重点看；
- 已看到什么；
- 来源在哪里；
- 还缺什么；
- 不能推出什么；
- 需要用户/供应链/报关行/认证机构确认什么。

### 7.5 默认不替用户做价值主张

Superleads 可以整理事实和信号，但不输出：

- 值得进入；
- 建议开发；
- 最佳客户；
- 推荐报价；
- 市场潜力高；
- 必然能成交；
- 最佳物流方式；
- 最终税率就是某值。

用户自己判断商业动作。

### 7.6 三个地理角色必须分开

尤其在产品出海市场分析中，必须区分：

- 出口申报国；
- 原产国 / 制造来源；
- 实际起运地 / 起运港；
- 目标销售国家/地区；
- 卖方所在国；
- 目的节点。

这不是框架洁癖，而是真实外贸业务里关税、合规、物流、预申报、贸易救济都会因此改变。

## 8. 当前 A-M 是否已经跑偏

结论：A-M 有明显 Superpowers 风格，但多数仍服务 Superleads 的外贸风险控制；风险在于继续往下做时可能过度内核化。

| 已做内容 | 是否跑偏 | 判断 |
|---|---|---|
| schema / validator / fixtures | 未跑偏 | 解决候选升级、路径泄露、错误断言等真实风险 |
| audit / export | 未跑偏 | 把状态、缺口、来源表格化给用户 |
| Skill 入口 / 路由 | 未跑偏 | 明确三条业务路线，避免市场分析变找客户 |
| Source Pack / Query Plan | 有轻微过度风险 | 必须继续强调 Pack 是来源入口，不是事实库 |
| SearchLog / Source / Observation | 基本合理 | 防搜索摘要黑箱；但不要变成用户可见主线 |
| collection / merge / pipeline | 工程上合理 | 解决用户给 URL/PDF 后怎么进入正式链路 |
| 下一步 EvidenceCard 队列 | 有跑偏风险 | 如果直接做，会继续加内部层；应先用真实样本验证用户价值 |

## 9. 当前最需要校准的风险

### 9.1 过度工程化风险

A-M 已经构建了较强的底层链路。继续做 N/O/P，如果仍然只围绕内部对象，容易变成：

```text
一个严密的证据处理框架，但还没有足够多真实外贸用户报告样本。
```

校准：接下来每个技术 Slice 必须绑定一个用户可见交付改善。

### 9.2 真实业务样本不足风险

当前产品市场分析主要围绕 Xing Heng / UNIQLO / Tianneng / XM Textiles 等样本。它们覆盖了锂电、纺织、目录、网页、价格参考，但还不够覆盖 Superleads 的全业务世界。

需要补充的真实样本方向：

| 样本类型 | 为什么需要 |
|---|---|
| 传统 B2B 工业零部件 | 验证不依赖电商价格和礼品节点 |
| 大宗商品 / 期货相关产品 | 验证价格、物流、散货/散杂世界模型 |
| 农产品 / 食品 / 植物材料 | 验证检验检疫、冷链、农残、季节窗口 |
| 危化 / 液体 / 粉末 | 验证 SDS、危险品、包装和运输限制 |
| 单一客户背调真实复杂主体 | 验证公司身份、品牌/域名/运营实体冲突 |
| 批量客户开发真实目录 | 验证候选池而不是只做市场矩阵 |

### 9.3 用户价值表达不足风险

目前很多实现已经能防错，但用户第一眼看到的价值应该是：

- 这批客户为什么被列出；
- 这个客户到底是谁；
- 这个产品进入目标市场有哪些客观条件；
- 哪些地方我需要补资料；
- 哪些结论不能乱下。

不是：

- 我们有多少个 graph object；
- pipeline 执行了几个阶段；
- eval 跑了多少条。

### 9.4 对 Superpowers 的依赖边界不清

以后文档中可以明确写：

> Superleads 借鉴 Superpowers 的执行纪律，但产品模型、对象、状态、交付语言和验收样本必须以外贸业务为准。

不应把 Superpowers 作为 Superleads 的用户可见依赖或产品卖点。

## 10. 去 Superpowers 化校准规则

以后任何新功能进入 active bet 前，先过这 10 个问题：

| 校准问题 | 通过标准 |
|---|---|
| 1. 它服务哪条 Superleads 路线？ | 批量客户开发 / 单客背调 / 产品出海市场分析之一 |
| 2. 用户可见收益是什么？ | 能说成外贸人话，而不是内部对象名 |
| 3. 它减少哪类真实误导？ | 如同名公司、候选税号、平台价、搜索摘要、来源受限等 |
| 4. 是否会诱导大模型做主观价值判断？ | 不会，或有明确阻断 |
| 5. 是否会把弱证据删掉？ | 不会；弱证据应降级保留 |
| 6. 是否会把内部流程暴露给用户？ | 不会；只展示人话字段 |
| 7. 是否必须现在做？ | 若只是框架完整性，进入 parking |
| 8. 是否有真实外贸样本能验收？ | 至少一个真实样本或业务 fixture |
| 9. 是否影响三条路线边界？ | 不混淆找客户、背调、市场分析 |
| 10. 是否可用 eval 防止关键误导？ | 必须有 pass/fail 或文档验收 |

## 11. 对下一步 Code Slice N 的重新判断

原建议：Code Slice N 做 EvidenceCard 草稿前人工复核队列。

Slice R 校准后的判断：

| 选项 | 状态 | 原因 |
|---|---|---|
| 继续做 EvidenceCard 草稿队列 | 暂缓 | 容易继续加内部层，用户可见价值不够直接 |
| 做用户材料包导入清单 | 可考虑 | 更贴近真实业务：产品手册、SDS、证书、标签、COO、提单、发票 |
| 做端到端真实样本运行文档 | 推荐优先 | 能验证 A-M 是否真的服务外贸用户，而不是只服务工作流 |
| 做批量客户开发/单客背调同样的产品内核复盘 | 推荐并行或下一步 | 避免产品市场分析把整个 Superleads 带偏 |

推荐下一步不是继续写 EvidenceCard 队列，而是：

> Slice S：用真实外贸任务跑一遍三条路线的用户可见样本，检查 Superleads 是否像外贸产品，而不是像工作流框架。

最小可选样本：

1. 批量客户开发：某产品 + 目标国家 + 客户类型，产出候选客户池样表。
2. 单客背调：一个真实公司/域名，产出表格化背调报告。
3. 产品出海市场分析：一个用户材料包 + 目标国，产出市场与准入矩阵。

## 12. 产品内核冻结语句

后续文档、代码和 Skill 设计都应遵守以下冻结语句：

> Superleads 是外贸业务情报产品，不是通用工作流框架。Superpowers 只提供执行纪律参考；Superleads 的产品对象、用户语言、状态词、证据边界和验收样本必须来自真实国际贸易业务。内部证据链的唯一目的，是让用户看到更可靠、更清楚、更不误导的客户、公司和产品市场信息。

## 13. 本轮非目标

本 Slice R 不做：

- 不改代码；
- 不新增 schema；
- 不新增 pipeline；
- 不重构 A-M；
- 不否定已完成证据链；
- 不引入 Superpowers 作为运行依赖；
- 不把 Superpowers 写成用户可见产品卖点。

## 14. 验收标准

- 能清楚区分“可参考 Superpowers 的执行纪律”和“Superleads 自己的外贸产品内核”。
- 能解释 A-M 为什么大部分仍然合理，以及哪里开始有过度工程风险。
- 能给出下一步的产品优先级校准：先跑真实三路线样本，再继续加内部证据层。
- 能形成一句冻结语句，供后续产品、Skill、代码、eval 共同遵守。
