# 产品出海市场分析：Skill 分工互证流程（Slice 4）

本文件冻结第一版 `产品出海市场分析` 的内部 Skill 分工与互证流程。它是产品规格，不是代码实现；不新增市场、法规、关税或物流事实。

一句话流程：**先把产品和贸易前提看清楚，再分头查不同事实域，最后互相挑错并表格化交付。**

## 1. Slice 4 边界

| 项目 | 本轮决定 |
|---|---|
| 目标 | 明确六个内部 Skill 怎么分工、怎么交接、怎么互相校验、什么时候打回上游 |
| 适用对象 | 对话报告、Markdown 样例、XLSX/CSV 工作簿、未来自动化 Skill / Agent / 脚本实现 |
| 首批样本 | Xing Heng `48V20Ah` LiFePO4 电池包；UNIQLO Men's Corduroy Overshirt `470177` |
| 本轮不做 | 不写代码、不改现有 Skill、不接新数据源、不做真实联网市场报告 |
| 输出 | Skill 责任边界、证据卡、互证矩阵、打回规则、冲突保留规则、两个样本流程示例 |

## 2. 设计原则

| 原则 | 人话说明 |
|---|---|
| 事实域分工，不按国家硬编码 | 不是“美国写一套、欧盟写一套、越南写一套”；而是按产品属性、市场、准入、出口、物流、复核六类事实域运行，再接各国来源路由 |
| 前序摘要不是证据 | 上一个 Skill 写的总结，只能帮助下一个 Skill 理解上下文，不能直接变成已核实事实 |
| 搜索只负责找门牌号 | 搜索结果和外部模型整理只算线索；必须打开网页、PDF、官方税则或用户文件后，才能支持字段 |
| 每个结论都有条件 | 税率、认证、标签、运输、趋势、价格都必须写明适用条件和缺口 |
| 认证先查目标要求，再看用户材料 | 用户不知道需要什么证书是常态；目的国准入 Skill 先列目标市场可能要求的认证/测试/注册/标签/包装，再单独核对用户是否已有材料 |
| 缺口不丢失 | 技术资料、贸易文件、实物标签、起运港、最终税号等缺口必须进入最终矩阵 |
| 冲突不强行调和 | 来源冲突时标 `有冲突待复核`，不让模型凭感觉选一个 |
| 只做客观参考 | 不输出“建议进入”“值得开发”“最佳运输方式”“推荐价格”等价值主张 |

## 3. 总流程

| 步骤 | 负责 Skill | 产物 | 通过条件 | 不通过时 |
|---:|---|---|---|---|
| 1 | 范围与产品属性识别 | 冻结 Brief、贸易前提表、产品属性触发项 | 产品版本、目的国、默认/用户指定出口国、原产国状态清楚 | 停在范围澄清或缺口矩阵 |
| 2 | 市场趋势、公开报告与价格参考 | 趋势/报告/价格/节日线索矩阵 | 每条市场信号有口径、日期、来源和限制 | 降级为 `未执行`、`来源受限` 或 `初步参考` |
| 3 | 目的国准入、税费与进口规则 | 准入、认证/测试/注册/标签/包装、目标国原产地证明/COO 要求、进口税费矩阵 | 产品属性、目的国、原产地、候选税号、贸易优惠/贸易救济条件、目标国要求状态和用户材料状态写清 | 打回属性 Skill 或降级为 `待专业确认` / `unable_to_verify` |
| 4 | 出口国监管、出口管制与检验要求 | 出口要求、管制、商检/检疫矩阵 | 出口申报国与原产国/起运国不混写 | 打回贸易前提或降级为 `待业务确认` |
| 5 | 运输方式、路线、港口与申报节点 | 运输方式、港口、时效区间、预申报节点矩阵 | 货物属性、包装、起运/目的节点、法定与操作截点分开 | 打回属性/贸易前提，或仅保留候选路径 |
| 6 | 交叉复核与表格化交付 | 最终报告、工作簿行、来源表、缺口表、冲突表 | 所有字段可追溯，禁止升级规则通过 | 阻断交付或退回对应 Skill 改写 |

说明：步骤 2-5 在逻辑上可以并行，但都必须消费同一版冻结 Brief；如果 Brief 改版，受影响的下游结果必须重跑或降级。

## 4. 共享证据卡

每个 Skill 交付的不是一段总结，而是一组“证据卡”。证据卡是后续互证和表格化输出的最小单位。

| 字段 | 必填方式 |
|---|---|
| 要支持的字段 | 如 `电池容量`、`候选 HTSUS`、`标签要求`、`海运预申报节点` |
| 当前值 | 原文值、派生计算值、候选值或状态值 |
| 状态 | 使用工作簿合同中的状态枚举：已核实、候选、初步参考、待技术资料确认等 |
| 来源类型 | 官方法规、官方税则、产品页、PDF、用户文件、Google Trends、平台价格、搜索线索等 |
| 来源定位 | 公开 URL、文件名、页码/章节/表格位置；不得只有“网上看到” |
| 来源日期 | 生效日期、发布日期、报告日期；没有就写 `日期未见` |
| 观察日期 | 本轮查看或抽取日期 |
| 适用范围 | 型号、国家、时间、运输情形、订单/批次、规格等 |
| 能支持什么 | 只写该来源直接支持的字段 |
| 不能支持什么 | 明确不能升级成的结论，如不能替代 UN38.3、不能证明最终税率 |
| 缺口/下一步 | 需要用户、供应商、报关行、认证机构或承运人补什么 |

证据卡不得只写“某 Skill 已确认”。如果无法定位到原始来源，只能作为 `候选`、`来源受限` 或 `待复核`。

## 5. 六个 Skill 的详细分工

### 5.1 Skill A：范围与产品属性识别

| 项目 | 要求 |
|---|---|
| 输入 | 用户描述、产品手册/PDF、官网 URL、用户粘贴的候选资料、目标国家/地区、默认或指定出口国、用户已提供的 COO/发票/提单/装箱单等贸易文件 |
| 必须输出 | 产品版本、贸易前提表、产品属性矩阵、触发项、关键缺口、用户贸易文件准备状态、可执行研究问题 |
| 重点识别 | 材质、用途、规格、带电/电池、磁性、液体、粉末、化学品、危险品、食品接触、皮肤接触、儿童用品、农产品、冷链、两用物项、超限/重大件、包装 |
| 不得输出 | 不猜 HS、不猜原产地、不写“无需认证/不是危险品/无出口限制”；不把用户未提供 COO 写成目标国不需要 |
| 交给下游 | 一版冻结 Brief，所有属性都带状态；未知项必须可见 |
| 必须打回 | 产品版本不唯一、目标国家缺失、出口申报国/原产国/起运国混淆、产品资料互相矛盾 |

### 5.2 Skill B：市场趋势、公开报告与价格参考

| 项目 | 要求 |
|---|---|
| 输入 | 冻结 Brief、当地语言关键词、英文关键词、同义词、可比规格、目标国家/地区 |
| 必须输出 | Google Trends 相对搜索兴趣矩阵、公开报告/统计/协会资料矩阵、线上价格参考、节日/季节窗口、适用品类的期货/指数线索 |
| 重点识别 | 2004 年以来可取得的长期趋势、公开市场资料、B2B/B2C/电商挂牌价、礼品节点、淡旺季公开证据、大宗商品期货/现货指数 |
| 不得输出 | 不把搜索兴趣写成销量，不把挂牌价写成成交价，不把线上渠道当作传统 B2B 客户范围，不给进入建议 |
| 交给下游 | 价格/趋势只作为市场参考；每条都写规格、币种、税运费、日期、限制 |
| 必须打回 | 关键词与产品不匹配、价格规格不可比、来源只有搜索摘要、没有日期却称“最新” |

### 5.3 Skill C：目的国准入、税费与进口规则

| 项目 | 要求 |
|---|---|
| 输入 | 冻结 Brief、产品属性触发项、目的国、原产国状态、候选 HS/HTS、技术资料状态、用户已提供/未提供的证书与测试文件状态 |
| 必须输出 | 目的国认证/测试/注册/标签/包装/安全要求、每项要求的触发条件、用户材料状态、进口限制、目标国 COO / proof of origin 要求、候选税号、基础税率列示、优惠/贸易救济/附加税核验项、计算口径 |
| 重点识别 | 官方法规、主管部门、海关税则、标签和包装要求、COO / proof of origin、origin marking、危险品/食品/农产品/纺织/电器等适用条件 |
| 不得输出 | 不给最终归类、最终税率或最终税额；不写产品已经合规；不把网页标签当实物标签；不把 COO 只作为用户缺口；不把 Made in 标识当 COO 文件；不把用户未提供证书写成目标国不需要认证；不把用户证书写成目标国已认可 |
| 交给下游 | 对物流 Skill 给出危险品、标签、包装和进口申报触发项；对交付 Skill 给出税费缺口 |
| 必须打回 | HS 过粗却计算税费、原产地等级不足却套优惠税率、技术资料缺失却判断合规、法规来源不是官方却写确定结论；无官方来源却写需要/不需要 COO；把用户证书状态与目标国认证要求混写 |

### 5.4 Skill D：出口国监管、出口管制与检验要求

| 项目 | 要求 |
|---|---|
| 输入 | 冻结 Brief、出口申报国、原产国、实际起运国/地、产品属性、候选 HS、最终用途/最终用户线索 |
| 必须输出 | 出口许可证、检验检疫、商检、出口管制、两用物项、制裁/最终用途核验路径、出口侧 COO 签发/申领程序线索、出口单证缺口 |
| 重点识别 | 出口申报国规则，而不是默认使用中国；农产品、化学品、危险品、两用物项、战略物资、大宗商品等触发条件 |
| 不得输出 | 不把原产国等同出口申报国；不把目的国 COO 清关要求写成出口国强制签发要求；不写“无出口限制”；不替代主管机关或报关专业判断 |
| 交给下游 | 给物流 Skill 提供出口申报和禁限运触发；给交付 Skill 提供出口侧待确认事项 |
| 必须打回 | 出口申报国未确认、HS/属性不足以判断、最终用途/最终用户可能影响管制但缺资料 |

### 5.5 Skill E：运输方式、路线、港口与申报节点

| 项目 | 要求 |
|---|---|
| 输入 | 冻结 Brief、货物属性、包装状态、起运地、目的港/交付地、出口/进口申报触发项、货量/件重/尺寸/温控等条件 |
| 必须输出 | FCL、LCL、空运、快递、铁路、公路、散货、散杂、RoRo、冷链、罐箱、危化、多式联运等候选方式矩阵；COO/发票/提单/装箱单与订舱、舱单、清关资料的操作节点关系 |
| 重点识别 | 常用港口/机场/口岸、常见运输区间、法定提前申报、船司/货代操作截点、危险品/冷链/超限限制 |
| 不得输出 | 不承诺船期，不写最佳运输方式，不把法定预申报和货代截单混成一句，不默认起运港；不把物流文件等同 COO 或目标国合规判断 |
| 交给下游 | 运输候选、适用条件、法定节点、操作节点、关键缺口 |
| 必须打回 | 缺包装/SDS/UN38.3/温控/尺寸重量却判断可走某方式；起运港未知却写固定路线；时效无来源却写确定区间 |

### 5.6 Skill F：交叉复核与表格化交付

| 项目 | 要求 |
|---|---|
| 输入 | 前五个 Skill 的证据卡、冻结 Brief、冲突/缺口记录、Slice 3 证据边界规则、工作簿合同 |
| 必须输出 | 用户可见 Markdown 报告、XLSX/CSV 行矩阵、来源表、缺口表、冲突表、目标国 COO 要求/用户材料状态分列检查、目标国认证/准入要求与用户证书状态分列检查、禁止升级自检结果 |
| 重点识别 | 来源是否可打开、字段是否被来源直接支持、状态是否过度乐观、日期是否足够支持“最新”、是否有价值判断 |
| 不得输出 | 不新增未证实事实，不把前序 Skill 摘要当证据，不替用户做进入市场或客户开发判断 |
| 允许动作 | 降级、拆行、补限制说明、标冲突、退回上游、阻断交付 |
| 必须打回 | 发现禁止升级、来源无法定位、税费/运输/合规/COO 要求无条件结论、目标国要求与用户材料混写、冲突未保留、缺口被删掉 |

## 6. 互证矩阵

| 被校验对象 | 主要校验方 | 校验重点 | 发现问题时 |
|---|---|---|---|
| 产品版本与属性 | Skill C / D / E / F | 法规、出口、物流研究是否发现新属性或属性冲突 | 打回 Skill A 更新 Brief；受影响下游重跑或降级 |
| Google Trends 与市场信号 | Skill F | 是否只是相对兴趣；关键词、地区、时间范围、日期是否清楚 | 改成 `初步参考`、`数据不足` 或 `未执行` |
| 线上价格与平台信息 | Skill A / F | 规格是否可比，是否被误写成成交价或传统 B2B 采购价 | 拆规格、补限制；不可比则降级 |
| 目的国准入 | Skill A / D / E / F | 是否依赖未确认技术属性、原产地、包装、运输情形 | 打回属性或贸易前提；结论降级 |
| 目标国认证/测试/注册/标签要求 | Skill A / C / D / E / F | 是否先回答目标市场可能要求什么，再单独展示用户材料状态；是否区分法律强制、运输文件、渠道/客户要求 | 无官方/权威来源则 `unable_to_verify` 或 `待专业确认`；用户未提供材料只能进入材料状态，不能反推规则 |
| 进口税费 | Skill A / C / F | HS、原产地、税基、有效税表、10 位后缀、origin proof / 优惠原产地条件是否齐全 | 不得输出最终税率/税额，只保留候选路径 |
| 目标国原产地证明要求 | Skill A / C / D / F | 是否把目标国规则与用户材料状态分列；是否区分 COO、proof of origin、origin marking、优惠原产地 | 无官方来源则 `unable_to_verify`；用户未提供只进入材料状态，不能反推规则 |
| 出口国要求 | Skill A / C / E / F | 出口申报国是否明确，是否混同原产国/起运国 | 打回贸易前提；改为待业务确认 |
| 运输路线与时效 | Skill A / C / D / F | 货物属性、包装、危险品、冷链、超限、申报节点是否匹配 | 改为候选方式；删除承诺性表达 |
| 来源与日期 | Skill F | 是否可打开、可定位、可复核，是否支持“最新” | 降级或阻断；来源受限进入缺口表 |

## 7. 三道门禁

### 7.1 门禁一：Brief 冻结门

没有通过 Brief 冻结门，只能输出“范围澄清 + 缺口表”，不能进入确定事实报告。

| 必须看清 | 允许状态 |
|---|---|
| 产品名称与版本 | 已确认 / 待用户确认 |
| 目的国/地区 | 已确认 |
| 出口申报国 | 已确认 / 使用可见默认值 / 待业务确认 |
| 原产国 | 已核实公开来源 / 待文件确认 / 未提供 |
| 贸易优惠/原产地证明诉求 | 已确认 / 未询问 / 不适用 / 待业务确认 |
| 实际起运地 | 已确认 / 待业务确认 |
| 关键产品属性 | 已核实 / 待技术资料确认 / 未提供 / 不适用 |

### 7.2 门禁二：证据来源门

任何字段进入 `已核实` 前，必须满足：

| 条件 | 说明 |
|---|---|
| 来源可定位 | 有 URL、文件名、页码、章节、表格或官方查询入口 |
| 来源能直接支持 | 来源只支持它明示的字段，不支持相邻推断 |
| 范围匹配 | 型号、国家、日期、标准、运输情形或订单批次匹配 |
| 日期可解释 | 有来源日期、有效日期、观察日期；否则不能称“最新” |
| 限制已写出 | 不能支持什么必须写在证据卡里 |

### 7.3 门禁三：交付边界门

交付前必须检查：

| 检查项 | 不通过表现 |
|---|---|
| 价值判断 | 出现“建议进入”“值得开发”“市场潜力高”“推荐价格”“最佳运输方式” |
| 税费升级 | 候选税号、基础税率被写成最终税率或最终税额 |
| 合规升级 | 证书/网页/测试报告被写成完整合规或其它标准合规 |
| 认证混写 | 用户未提供证书被写成目标国不需要认证；用户提供证书被写成目标国已认可 |
| 物流升级 | 候选方式被写成可出运、承诺交期或固定港口 |
| 搜索黑箱 | 搜索摘要、外部模型整理、前序摘要直接进入已核实字段 |
| 缺口丢失 | 未提供、未执行、来源受限、有冲突的信息没有进入最终表格 |

## 8. 打回上游规则

### 8.1 必须打回，不能只改措辞

| 场景 | 打回给谁 | 原因 |
|---|---|---|
| 产品版本不唯一 | Skill A | 所有法规、税费、价格和物流都可能不适用 |
| 目的国缺失 | Skill A | 市场、准入、税费和物流无法确定范围 |
| 出口申报国、原产国、实际起运国混写 | Skill A | 出口要求、税费和路线前提不同 |
| 技术属性缺失却输出合规/运输结论 | Skill A + 对应事实 Skill | 缺 SDS、UN38.3、BOM、标签、包装等关键证据 |
| 用户证书状态与目标国认证要求混写 | Skill C + Skill F | 用户没给证书不等于不需要认证；用户给了证书也不等于目标国认可 |
| 来源只有搜索摘要或外部模型整理 | 对应事实 Skill | 不满足证据来源门 |
| 官方税则缺最终归类条件却输出最终税率 | Skill C | 税费表达越界 |
| 物流写成承运承诺或最佳方式 | Skill E | 运输表达越界 |
| 来源冲突未记录 | 对应事实 Skill + Skill F | 不能强行二选一 |

### 8.2 可以不打回，但必须降级

| 场景 | 降级方式 |
|---|---|
| Google Trends 没有有效数据 | `数据不足` 或 `未执行` |
| 价格来源规格不可完全比 | `初步参考`，并写不可比原因 |
| 付费报告只能看到摘要 | `来源受限`，只写可见内容 |
| 常见港口/路线只有公开经验资料 | `候选` 或 `初步参考`，不写固定路线 |
| 法规来源是专业解释但非主管机关 | `初步参考` 或 `待专业确认` |
| 日期未见 | 不称“最新”，写 `日期未见` 或观察日期 |

## 9. 状态流转规则

| 从 | 到 | 允许条件 |
|---|---|---|
| 搜索线索 | 候选 | 打开或记录到待核验 URL，但尚未直接抽取事实 |
| 候选 | 已核实 | 原始来源可打开、字段直接可见、范围和日期匹配 |
| 已核实 | 待专业确认 | 字段本身可见，但最终适用需要报关/认证/承运人/主管机关判断 |
| 已核实 | 有冲突待复核 | 另一个同等或更高优先级来源给出不同结果 |
| 初步参考 | 已核实 | 找到官方、原始或完整来源直接支持 |
| 任何状态 | 未执行 | 本轮没有做该模块采集，不得沿用旧结论 |
| 任何状态 | 待技术资料确认 | 缺少 SDS、UN38.3、BOM、标签、规格书、包装等技术文件 |

禁止状态流转：`搜索摘要 -> 已核实`、`候选税号 -> 最终税率`、`产品页标签 -> 实物标签合规`、`运输候选 -> 可出运/最佳方式`、`用户未提供 COO -> 目标国不需要 COO`、`Made in 标识 -> COO 文件要求`、`优惠 proof of origin -> 所有进口都需要 COO`、`用户未提供证书 -> 目标国不需要认证`、`用户提供证书 -> 目标国已认可/产品已合规`、`证书入口 -> 已具备认证`。

## 10. 缺口、冲突与未执行的保留方式

| 类型 | 最终怎么保留 |
|---|---|
| 缺技术资料 | 写入 `产品档案与触发项`、`产品准入与合规要求`、`运输方式、路线、港口与申报节点`、`信息来源与待确认事项` |
| 缺贸易文件 | 写入 `市场事实总览`、`产品准入与合规要求`、`出口国要求`、`进口税费`、`信息来源与待确认事项`；COO 需求仍由目标国规则单独判断 |
| 来源冲突 | 双方来源分行列出，状态为 `有冲突待复核`，不合并成单一结论 |
| 未执行模块 | 对应工作表保留 `未执行` 行，说明本轮未采集，不能形成结论 |
| 来源受限 | 只写可见内容、限制和下一步，不补猜付费墙或搜索摘要里的数字 |
| 不适用 | 必须有排除依据；没有依据时不能写不适用 |

## 12. 两个样本的流程示例

### 12.1 Xing Heng `48V20Ah` LiFePO4 电池包：越南原产线索，出口美国

| Skill | 本样本应产出 | 必须避免 |
|---|---|---|
| Skill A | 识别 `48V20Ah`、Design No. `BAT001.02`、LiFePO4、960 Wh 派生计算、越南制造公开来源、UN38.3/SDS/包装/出口申报国/起运港缺口 | 不把越南制造线索写成正式 COO；不默认海防港 |
| Skill B | 若执行，只能把 Google Trends 写成相对搜索兴趣；价格必须限定同电压、容量、化学体系、用途和日期 | 不写销量增长；不把挂牌价写成成交价 |
| Skill C | 美国锂电进口/运输法规、美国 COO/proof of origin 条件核验、候选 `8507.60.00`、基础税率列示、Chapter 99 待核验、UN38.3/SDS 缺口 | 不把 QCVN/Vietnam Register 当 UN38.3；不写最终税率 |

| Skill E | FCL/LCL/空运/快递都只能作为候选组织方式；锂电文件、包装和承运条件是前置缺口 | 不写普通货运输、可直接空运/快递、最佳方式 |
| Skill F | 阻断任何“UN38.3 已具备”“无需 SDS”“最终税率 3.4%”“起运港海防”的越界表达 | 不补猜市场结论或运输结论 |

## 13. 用户可见表达要求

| 用户关心的问题 | 应该怎么说 |
|---|---|
| 现在能确认什么 | 用 `已核实` / `派生计算` 明确列出来源支持的字段 |
