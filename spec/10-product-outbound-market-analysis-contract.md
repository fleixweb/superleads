# 产品出海市场分析产品合同

## 1. 路线与边界

### 1.1 路线

`产品版本 + 目标国家/地区 + 贸易前提 -> 产品出海市场分析 -> 客观市场与准入信息矩阵`

它是 Superleads 的第三条独立路线：

| 路线 | 要解决的问题 | 不做什么 |
|---|---|---|
| 批量客户开发 | 按用户当前 B2B 范围发现与整理客户 | 不替用户做产品市场准入判断 |
| 单一客户背调 | 核实一个指定对象、其关系、公开信息和联系入口 | 不做通用市场研究 |
| 产品出海市场分析 | 整理产品在一个市场的市场、准入、税费、出口与物流事实 | 不生成客户名单或市场进入主张 |

### 1.2 客观性约束

交付不得包含：`值不值得进入`、`建议进入`、`市场潜力高`、`推荐价格`、`最佳运输方式`、`应重点开发哪类客户`、采购意愿或客户价值判断。

可以包含：事实、出处、日期、适用条件、计算公式、公开参考区间、未知项、来源受限、复核动作。任何“上升、下降、波动、增加、减少”都必须说明其具体指标和时间范围。

## 2. 输入合同

### 2.1 最小输入

| 输入 | 作用 | 缺失时的处理 |
|---|---|---|
| 产品名称与明确版本 | 形成研究对象 | 仅能形成范围澄清，不进行实质结论 |
| 目标国家/具体目的国 | 确定市场、进口法规和税费 | 仅能建立待选市场范围 |
| 卖方/出口申报国 | 确定出口国规则 | 默认为中国，但必须向用户可见且可修改 |
| 原产国 | 确定关税优惠、贸易救济与原产地规则 | 税费只能显示待确认 |
| 实际起运国/城市/港口 | 确定路线与出口操作条件 | 物流只能显示候选路径 |
| 目标交付地或目的港（如已知） | 确定港口、内陆段和申报节点 | 可先按目的国列出待确认港口 |

卖方所在国、出口申报国、原产国、实际起运国和目的国必须分别建模。它们可以相同，也可以不同。

### 2.2 产品档案与触发矩阵

产品档案不是封闭品类表，而是可扩展的事实矩阵。每个属性都必须标记为 `已确认`、`不适用`、`未提供`、`待技术资料确认` 或 `来源受限`。

| 属性族 | 最低需承载的信息 |
|---|---|
| 商业与技术 | 名称、用途、型号、规格、材质、成分、等级、部件/配件、目标用途 |
| 物理与运输 | 尺寸、重量、超限、液体、气体、粉末、磁性、温控、保鲜期、压力容器 |
| 电气与安全 | 带电池、电池类型/容量、纯电、无线/射频/蓝牙、激光、电气参数 |
| 化学与危险品 | 化学成分、SDS、CAS/EC、UN 编号、危险类别、易燃/腐蚀/毒性/气雾剂 |
| 人体与消费安全 | 食品接触、直接皮肤接触、儿童用品、玩具、医疗/健康、PPE、化妆品 |
| 农业与生物 | 食品、蔬果、花卉、茶叶、种子、植物/动物材料、木材、皮革、农残、检疫、冷链 |
| 战略与知识产权 | 两用物项、加密、军民两用、最终用途/最终用户、制裁、商标/专利线索 |
| 贸易分类 | HS 候选与归类状态、原产地、包装、标签语言、内外包装材料 |

产品本体、部件、内置电池、内包装和外包装可分别记录属性。一个产品可以同时触发多个条件，不能被迫归入单一类别。

### 2.3 属性不足时的降级

无技术资料或关键属性未确认时，系统必须展示“可能触发的核验路径”和缺失材料；不得输出“无需认证”“不是危险品”“无出口限制”“税率为 X”之类确定结论。

## 3. 六个 Skill 的职责与互证

| Skill | 负责事实域 | 必须交付 | 不得做什么 | 复核关系 |
|---|---|---|---|---|
| 范围与产品属性识别 | 产品版本、贸易前提、属性与未知项 | 分析 Brief、属性矩阵、触发项 | 不猜技术参数或 HS | 为其余 Skill 提供条件；后续发现冲突必须退回修订 |
| 市场趋势、公开报告与价格参考 | Google Trends、公开统计、协会、公开行业资料、平台/指数/期货参考 | 指标口径、时间线、价格信号矩阵 | 不把兴趣或挂牌价写成销量或成交价 | 交付复核者回看原始来源与日期 |
| 目的国准入、税费与进口规则 | 目的国法规、认证、标签、包装、进口税费、贸易救济 | 适用条件、法律/税费矩阵、税额计算口径 | 无产品条件或税则条件时不给确定结论 | 出口与物流 Skill 核对申报、原产地和运输触发条件 |

| 运输方式、路线、港口与申报节点 | 货运方式、路径、港口/机场/口岸、法定预申报、操作截点 | 运输与申报节点矩阵 | 不承诺船期、价格或承运可行性 | 核对货物属性、危险品/冷链/超限条件和出口进口规则 |

## 4. 事实与证据合同

### 4.1 来源等级

| 信息域 | 优先来源 | 可以作为辅助参考 | 不可作为事实依据 |
|---|---|---|---|
| 法规、认证、关税、出口管制 | 主管部门、海关、官方税则、官方法规库 | 认证机构/报关行/律师公开解释，且标待专业确认 | 搜索摘要、无出处博客、模型记忆 |
| 运输与预申报 | 海关、港口、承运人、官方申报制度 | 公开货代说明，且区分操作经验与法定节点 | 未核实论坛、泛化时效承诺 |
| 市场趋势与行业规模 | Google Trends、官方统计、协会、可读取公开报告 | 专业咨询机构公开摘要，标明可见范围 | 付费报告搜索摘要推导出的数字 |
| 价格 | 公开平台、公开询报价、指数、交易所、官方统计 | 行业媒体公开价格线索 | 无规格、无币种、无日期的价格叙述 |

搜索结果只能用于发现来源，不能直接作为事实。每个事实至少记录来源、原文/可核实定位、观察日期；法规、税费和管制还必须记录生效日期或明确“生效日期未见”。

### 4.1.1 外部模型与用户转述的处理

| 输入类型 | 可用于什么 | 不可用于什么 | 必须动作 |
|---|---|---|---|
| ChatGPT、Codex 以外模型、搜索摘要、用户粘贴的网络整理 | 候选线索、待打开 URL、待核验字段清单 | 已核实事实、Claim、税率、认证、原产地或运输结论 | 重新打开原始网页、抽取文件或读取官方来源后再入表 |
| 用户提供的产品手册 PDF / 目录 / 官网 URL | 可作为公开来源或用户提供文件线索 | 自动证明原产地、HS、认证、可运输性 | 记录文件名/来源、抽取页码/定位、观察日期和字段状态 |
| 用户提供的业务文件，如 COO、发票、提单、装箱单 | 可作为业务前提或贸易文件证据 | 替代主管机关最终裁定 | 标明文件类型、适用订单/型号、日期和仍需专业确认的部分 |

外部模型搜索结果不得直接写入“已核实”字段；只能进入“候选线索”。如果无法打开来源或无法抽取文件，交付必须停在待确认矩阵。

### 4.1.2 原产地证据等级

| 等级 | 证据类型 | 可以怎么写 | 不得怎么写 |
|---|---|---|---|
| L0 | 无来源或只有模型/搜索摘要 | 原产地未核实 | 不得写原产国 |
| L1 | 产品页、品牌页公开写明 Production / Made in / manufactured in | 公开页面显示某国生产/制造 | 不得等同海关最终原产地裁定 |
| L2 | 制造商证书、测试报告、工厂资料显示制造商/装配厂与型号 | 公开文件支持该型号的制造/装配来源 | 不得替代 COO、发票、提单或进口国原产地规则判断 |
| L3 | COO、商业发票、装箱单、提单、出口报关单等订单级贸易文件 | 订单/批次文件显示原产或起运信息 | 不得泛化到所有 SKU 或所有批次 |
| L4 | 主管机关、海关预裁定、官方原产地裁定或正式适用证明 | 按该裁定条件展示 | 不得超出裁定产品、时间和条件 |

原产国、出口申报国、实际起运国/港、卖方所在国仍需分别展示；一个等级较高的原产地证据也不能自动补齐装运港或出口申报国。

### 4.1.3 认证、测试报告与 SDS 边界

| 文件类型 | 必须核对 | 可支持 | 不可自动支持 |
|---|---|---|---|
| 产品证书 / 型式批准 | 颁发机构、法规/标准号、型号、日期、覆盖范围 | 该证书范围内的产品状态 | 其它国家认证、运输危险品测试、SDS、海关归类 |
| 测试报告 | 测试标准、样品型号、报告日期、测试项、结论页 | 测试报告列出的项目 | 未列标准下的合规，例如把 QCVN 测试当 UN38.3 |
| SDS / MSDS | 型号/化学体系、版本、签发日期、危险分类、运输信息 | 危险品与承运核验材料之一 | 替代 UN38.3、包装证明、承运人接受或最终法规判断 |
| UN38.3 test summary / report | 型号、电芯/电池、版本、测试标准、签发主体 | 锂电运输核验关键文件 | 替代 SDS、包装、UN 编号运输情形或承运确认 |

只要文件标题、标准号或适用范围不匹配，就必须显示“待技术资料确认”，不得用相邻证书补空。

### 4.1.4 HS/HTS 候选边界

官方税则搜索结果只能形成候选归类路径。用户可见表格必须拆开：`候选税号`、`归类依据缺口`、`10 位统计后缀`、`原产国`、`有效日期`、`基础税率`、`优惠/协定`、`贸易救济/Chapter 99`、`其它税费`、`计算税基`。

缺少实物归类、10 位后缀、原产地或有效税表时，不得把基础税率写成“最终税率”或“最新税率”。

### 4.2 “最新”与时效

“最新”只能用于有实际来源日期、有效日期或复核日期的记录。没有这些日期时，只能写“已观察，需复核”。

### 4.3 Google Trends

对每一个趋势条目记录关键词或 Topic、当地语言同义词、国家/地区、搜索类型、类目、实际可取得时间范围、数据提取日期和比较口径。尽可能覆盖 2004 年至今；若实际数据起点更晚，展示真实起点。

长期标签仅可为“该检索口径下的相对搜索兴趣上升/下降/平稳/波动/数据不足”，不等于销量、GMV、进口量、采购量或市场份额。公开统计和可读取行业资料应作为独立信号并列展示，不可用其摘要补全缺失数据。

### 4.4 价格信号

| 信号源 | 适用范围 | 必填口径 | 不得推导 |
|---|---|---|---|
| 线上 B2B/B2C、电商页面 | 可线上展示的标准化产品 | 规格、币种、税/运费、促销状态、观察日期 | 真实成交价、传统 B2B 采购价 |
| 公开询报价、目录 | 工业品、项目品、零部件 | 规格、交货条件、币种、日期 | 最终合同价 |
| 现货报价和价格指数 | 原材料、大宗、农产品 | 品级、产地、交付地、单位、日期 | 任意目的地的出口成交价 |
| 期货市场 | 金属、能源、粮食等适用标的 | 交易所、合约、品种等级、交割地、合约月、单位、币种、日期 | 现货价、出口报价、投资或套保建议 |

### 4.5 税费

确定税费必须同时具备产品版本、HS 归类状态、原产国、目的国、有效税表、生效日期和税基。矩阵应拆开基础关税、优惠条件、VAT/GST、贸易救济税、其他附加税与计算公式。缺任何关键前提时，显示待确认而不是给单一“最新税率”。

## 5. 物流、运输与申报合同

### 5.1 运输方式与货运组织方式

| 方式 | 典型分析重点 |
|---|---|
| 海运整柜 FCL | 起运港、目的港、船期、港到港区间、截关、舱单/预申报 |
| 海运拼箱 LCL | 拼箱仓截货、开船港、拆箱港/CFS、常见目的地操作与时间区间 |
| 国际快递 | 适用货型、计费重、清关模式、偏远/燃油等公开附加项、禁限运条件 |
| 空运与空运拼货 | 机场、航班/中转、交货与截单、计费重、危险品/电池限制 |
| 铁路整箱/拼箱 | 班列、换装、边境、整柜/拼箱、常见时间区间 |
| 国际陆运整车/零担 | 口岸、边境申报、转关、常见时间区间 |
| 邮政/跨境小包/专线 | 低值小件适用范围、清关规则、追踪、禁限运和赔付边界 |
| 散货船 | 煤炭、矿产、粮食、钢材等；船型、泊位、水深、堆场、装卸能力 |
| 散杂/重大件 | 钢材、工程设备、风电等；件重件尺、吊装、绑扎、甲板/舱内、港口能力 |
| 滚装船 RoRo | 汽车、工程机械；车辆状态、燃油/电池限制、港口与船期 |
| 冷链、罐箱与危化 | 温湿度、预冷、气调、SDS/UN、危险品申报、设备和港口限制 |
| 多式联运 | 各运输段、交接港/站、边境、责任与时间构成 |

运输方式与产品属性必须分开：锂电、液体、磁性、粉末、温控、超限、生物检疫和危险品属性可能同时影响多种运输方式。时效只能表述为有来源的常见区间，不能写成船公司、航空公司、快递公司或货代承诺。

### 5.2 申报节点

每条申报或操作记录必须区分以下项目：

| 项目 | 必填内容 |
|---|---|
| 法定提前申报 | 制度/法规、适用货物、申报主体、触发节点、法定截止时间、官方来源 |
| 承运人/货代操作截点 | 具体承运人或货代的公开操作要求、截单/截货/截关时间、来源日期 |
| 港到港或门到门区间 | 路径、运输方式、货物前提、时间区间、主要不确定因素 |
| 清关与内陆段 | 目的地清关、查验、转关、内陆段和不确定因素 |

法定提前申报与船司/货代操作截止时间不得合并为“提前几天申报”。

## 6. 用户交付合同

### 6.1 对话展示

默认采用分组标题、Markdown 表格与简短要点，而不是长篇叙述。每张表最多六列。Mermaid 仅可用于有来源支撑的运输链路、申报节点和属性触发关系，不作装饰性图示。

### 6.2 XLSX/CSV 信息矩阵

完整交付至少包含下列工作表：

1. `市场事实总览`
2. `产品档案与触发项`
3. `长期需求与搜索趋势`
4. `公开市场资料与行业信息`
5. `线上市场与价格参考`
