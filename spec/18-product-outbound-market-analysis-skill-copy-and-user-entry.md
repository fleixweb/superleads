# 产品出海市场分析：Skill 文案与用户入口设计（Slice 7）

本文件冻结 `产品出海市场分析` 的用户入口、意图识别、首轮回应、追问文案和未来 Skill 文案草案。它不是代码，不修改现有 Skill，不新增路由实现。

一句话入口：**用户给一个产品和目标国家/地区，系统整理这个产品出海到当地的趋势、价格参考、准入、税费、出口要求、物流和外部因素；只给客观参考，不生成客户名单，不判断值不值得做。**

## 1. Slice 7 边界

| 项目 | 本轮决定 |
|---|---|
| 目标 | 明确用户怎么进入“产品出海市场分析”、系统怎么识别、怎么用人话追问、怎么避免误路由 |
| 当前仍不做 | 不写 Skill 代码、不改 `using-superleads`、不新增命令、不接真实搜索 |
| 覆盖入口 | ChatGPT app、Codex CLI、未来 CLI/GUI/API 均可复用的文案和路由逻辑 |
| 关键边界 | 不生成客户名单，不做市场进入建议，不把线上渠道变成传统 B2B 客户范围 |

## 2. 用户心智定位

| 用户说法 | 系统理解 |
|---|---|
| “帮我分析这个产品出口美国” | 产品出海市场分析 |
| “这个产品在德国市场怎么样” | 产品出海市场分析，但只给客观参考，不说值不值得做 |
| “查一下关税、认证、物流、趋势” | 产品出海市场分析 |
| “帮我找美国买家/客户/进口商” | 批量客户开发，不是产品市场分析 |
| “背调这个公司/网站/邮箱” | 单一客户背调，不是产品市场分析 |
| “我有一批客户名单，帮我补全” | 表格补全/客户开发，不是产品市场分析 |

用户不需要懂 “Skill / graph / evidence card / eval”。用户只需要知道：**我给产品和国家，它给我一张能复核的信息矩阵。**

## 3. 入口名称与对外文案

| 场景 | 文案 |
|---|---|
| 功能名称 | 产品出海市场分析 |
| 一句话说明 | 按产品和目标国家/地区，整理趋势、公开价格参考、准入合规、进口税费、出口要求、运输路线和近期外部因素。 |
| 边界说明 | 只做客观资料整理，不替你判断是否值得进入，也不自动生成客户名单。 |
| 默认出口国说明 | 默认按中国出口申报国处理，但你可以改成任何国家/地区。 |
| 缺资料说明 | 技术资料、原产地、起运港、最终税号不清楚时，会写成待确认，不会帮你猜。 |

## 4. 触发词与非触发词

### 4.1 明确触发产品出海市场分析

| 用户表达 | 触发原因 |
|---|---|
| 产品出海市场分析：某产品到某国 | 直接命名功能 |
| 分析某产品出口到某国的市场、关税、认证、物流 | 产品 + 目的国 + 事实域 |
| 某产品在某国 Google Trends、价格区间、淡旺季 | 市场趋势/价格参考 |
| 某产品进入某国有什么认证/包装/标签要求 | 目的国准入 |
| 某产品从中国/越南/土耳其出口到美国的税率和路线 | 出口国/原产国/目的国路径 |
| 某农产品/化工品/锂电/纺织品去某国要注意什么资料 | 产品属性触发合规/运输/出口要求 |

### 4.2 不触发，优先走其它路线

| 用户表达 | 应走路线 | 原因 |
|---|---|---|
| 帮我找某产品美国客户 | 批量客户开发 | 用户要客户名单 |
| 帮我开发某国家进口商 | 批量客户开发 | 用户要买家/客户 |
| 背调这个公司/域名/品牌 | 单一客户背调 | 指定对象核验 |
| 帮我整理这批客户表格 | 客户表格补全 | 用户给的是客户名单 |
| 查这个邮箱是谁的 | 单一对象/联系方式核验 | 不是产品市场 |

### 4.3 容易误判的表达

| 用户表达 | 默认处理 |
|---|---|
| “这个产品美国市场能不能做” | 转成产品出海市场分析；回应“我会整理客观资料，是否做由你判断” |
| “这个产品在美国好不好卖” | 转成趋势/公开市场/价格参考，不写真实销量结论 |
| “帮我看这个产品怎么卖给美国客户” | 如果用户要客户名单，走批量开发；如果要市场/准入/价格/物流，走产品出海市场分析 |
| “这个产品出口美国有哪些目标客户” | 走批量客户开发；产品市场分析里的线上渠道只能作参考 |
| “分析美国市场，然后找客户” | 拆成两个阶段：先产品出海市场分析，再由用户确认是否进入客户开发 |

## 5. 首轮回应模板

### 5.1 信息足够时

```text
我理解你要做的是：产品出海市场分析。
本轮对象：{产品版本} → {目的国/地区}。
默认出口申报国：{默认/用户指定出口国}；原产国/起运地如果资料不足，会保留待确认。
我会按趋势、公开价格参考、准入合规、进口税费、出口要求、运输路线和近期外部因素整理成表格；不输出是否值得进入，也不生成客户名单。
```

### 5.2 缺目标国家/地区时

```text
可以做，但还缺一个会改变结论的关键前提：目标国家/地区。
请给一个具体国家/地区；如果是欧盟，也建议先指定落地国家，因为税费、标签、EPR、清关和港口会按国家变化。
```

### 5.3 缺产品版本时

```text
可以做，但现在产品还不够具体。
请尽量给产品型号、材质/成分、用途、规格，或者直接给产品页/PDF；否则只能先做“待确认项清单”，不能给准入、税费和物流的确定路径。
```

### 5.4 用户问“值不值得做”时

```text
我可以帮你做产品出海市场分析，把趋势、公开价格、准入、税费、物流和风险因素整理清楚；是否进入这个市场由你判断。
报告里不会写“建议进入/不建议进入”，会把可核实事实、限制和待确认项列出来。
```

### 5.5 用户同时要求市场分析和找客户时

```text
这可以拆成两步：
1. 先做产品出海市场分析，看趋势、价格参考、准入、税费、出口和物流；
2. 如果你看完后决定继续，再按批量客户开发去找客户。
本轮我先按产品市场分析处理，不自动生成客户名单。
```

## 6. 最小追问规则

| 情况 | 追问策略 |
|---|---|
| 缺产品 | 必问，无法开始实质分析 |
| 缺目的国/地区 | 必问，市场、法规、税费、物流都无法落地 |
| 缺出口申报国 | 默认中国，但必须明说“可修改” |
| 缺原产国 | 不阻断全报告，但税费、优惠、贸易救济只能待确认 |
| 缺起运港/机场 | 不阻断全报告，但物流只能列候选路径 |
| 缺 SDS/UN38.3/BOM/标签/包装 | 不阻断全报告，但相关合规和运输只能待技术资料确认 |
| 用户给 PDF/网页 | 可以接收，先作为产品资料/公开来源线索，不自动证明原产地或合规 |

首轮最多问 3 个短问题。推荐顺序：

1. 目标国家/地区是哪里？
2. 这个产品的明确型号/规格/材质是什么？有产品页或 PDF 吗？
3. 出口申报国和原产国是否已确定？如果没说，是否先按中国出口申报国做默认前提？

## 7. 产品属性提示文案

当用户只给很泛的产品名时，不发长问卷，用一段人话提示：

```text
为了避免把认证、税费和运输判断错，我会特别看这些触发项：
是否带电/带电池、是否液体/粉末/磁性、是否化学品或危险品、是否接触食品/皮肤/儿童、是否农产品/冷链、是否大宗/散杂/滚装/超限、是否两用物项或受出口管制。
你有资料就给；没有的我会写“待确认”，不会默认猜。
```

## 8. 用户可提交材料说明

| 材料 | 怎么用 | 不能自动证明什么 |
|---|---|---|
| 产品页 URL | 抽取型号、参数、材质、页面声明 | 不自动证明最终原产地、HS、合规 |
| 产品手册/PDF | 抽取规格、成分、结构、用途、包装线索 | 不自动证明出口申报国或最终归类 |
| SDS / MSDS | 支持危险品和运输核验线索 | 不替代 UN38.3、包装、承运确认 |
| UN38.3 | 锂电运输关键文件 | 不替代 SDS、包装和 UN 编号情形判断 |
| BOM / 标签照片 | 支持成分、辅料和实物标签核验 | 不自动等于进口国专业合规结论 |
| 发票/提单/装箱单/COO | 支持订单级原产、起运、数量、包装 | 不泛化到所有 SKU 或所有批次 |

## 9. 用户输出承诺文案

默认用户看到的是分组表格，不是长篇文章：

| 分组 | 用户能看到什么 |
|---|---|
| 先看边界 | 已核实、候选、待确认、未执行 |
| 产品档案与触发项 | 型号、材质、规格、危险品/电池/纺织/农产品等触发项 |
| 趋势与公开市场资料 | Google Trends 相对搜索兴趣、公开报告/统计/协会资料 |
| 线上市场与价格参考 | 公开挂牌价、平台价、指数/期货线索和限制 |
| 季节与节日窗口 | 法定节假日、礼品/季节属性的公开节点 |
| 准入与合规 | 认证、标签、包装、安全、检疫、危险品等 |
| 进口税费 | 候选 HS/HTS、基础税率、附加税、税基和待确认项 |
| 出口国要求 | 出口申报国的许可证、商检、检疫、出口管制 |
| 运输与申报节点 | FCL/LCL/快递/空运/铁路/陆运/散杂/RoRo/冷链等候选路径 |
| 近期外部因素 | 有来源和日期的政治、战争、灾害、金融、假期等因素 |
| 来源与待补材料 | 公开来源、文件、观察日期、下一步需补资料 |

## 10. 未来 Skill 文案草案

### 10.1 Skill 名称草案

| 项目 | 草案 |
|---|---|
| Skill 名 | `analyzing-product-outbound-market` |
| 中文显示 | 产品出海市场分析 |
| 简短描述 | 当用户需要按产品和目标国家/地区整理市场趋势、公开价格参考、准入合规、进口税费、出口要求、运输路线和外部因素时使用。 |

### 10.2 `description` 草案

```text
Use when the user asks for objective outbound market analysis for a specific product and target country/region, including Google Trends/search-interest signals, public market and price references, destination-market compliance, import duties/taxes, export-country requirements, logistics routes, customs pre-filing nodes, and recent external factors. Do not use for customer discovery, lead lists, single-company background research, or market-entry recommendations.
```

### 10.3 未来 Skill 工作流草案

| 步骤 | 行为 |
|---|---|
| 1 | 识别是否为产品出海市场分析入口；若用户要客户名单则转批量客户开发 |
| 2 | 建立产品、目的国、出口申报国、原产国、起运地和资料缺口 Brief |
| 3 | 只问最多 3 个会改变结论的问题；默认出口申报国可为中国但必须可见 |
| 4 | 调用六个事实域 Skill 或对应流程：属性、市场、目的国、出口国、物流、交叉复核 |
| 5 | 每条事实必须形成 EvidenceCard；搜索摘要和前序 Skill 摘要不能当事实 |
| 6 | 按 12 张表/Markdown 分组交付，保留未执行、待确认、冲突和来源受限 |
| 7 | 不输出市场进入建议、客户名单、推荐价格、最佳运输方式 |

### 10.4 未来 Skill 硬约束草案

| 约束 | 说明 |
|---|---|
| 不生成客户名单 | 即使看到线上渠道和目标客户线索，也只作为市场参考 |
| 不做价值判断 | 不写建议进入、值得开发、市场潜力高 |
| 不把趋势写成销量 | Google Trends 是相对搜索兴趣 |
| 不把价格写成成交价 | 平台/电商/B2B 价格是公开挂牌或参考 |
| 不把候选税号写成最终税率 | 税费必须保留归类、原产地、税基和日期条件 |
| 不把网页/证书升级完整合规 | 网页标签、QCVN、测试报告、SDS、UN38.3 各有边界 |
| 不猜起运港 | 常用港口只能是候选参考 |
| 不暴露内部对象 | 用户表格不出现 graph、claim、EvidenceCard、hash、本地路径 |

## 11. 未来 `using-superleads` 路由文案草案

后续实现时，`using-superleads` 可增加一个入口判断：

```text
如果用户请求的核心是“一个产品进入/出口到某个国家或地区的市场、趋势、价格、准入、税费、出口要求、物流和外部因素”，且没有要求生成客户名单或背调指定公司，则路由到 `产品出海市场分析`。
```

用户可见四行理解：

```text
我理解你要分析的是：{产品} 出海到 {目的国/地区}。
本次不生成客户名单，也不判断是否值得进入。
我会重点整理：趋势、价格参考、准入、税费、出口要求、物流和外部因素。
缺原产地、起运港、SDS、UN38.3、BOM、标签等资料时，会列为待确认。
```

## 12. 示例入口

### 12.1 用户可以这样说

```text
做一个产品出海市场分析：48V20Ah LiFePO4 电池包，越南原产，出口美国。
```

```text
分析中国原产男式棉制灯芯绒衬衫出口美国的趋势、价格参考、标签要求、关税和物流。
```

```text
我有一个产品手册 PDF，帮我看这个产品出口德国需要哪些认证、包装、标签、税费和运输注意点。
```

```text
以中国为默认出口国，分析这个带电池产品到加拿大的 Google Trends、公开价格、准入门槛和物流路线。
```

### 12.2 系统不应该这样理解

| 用户说法 | 不应该 |
|---|---|
| “分析市场” | 自动生成客户名单 |
| “价格区间” | 输出推荐报价 |
| “趋势上升” | 写销量增长 |
| “有美国市场” | 写值得进入 |
| “常用港口” | 写固定起运港/最佳路线 |

## 13. 两个样本的首轮回应示例

### 13.1 Xing Heng 锂电样本

```text
我理解你要做的是：产品出海市场分析。
本轮对象：Xing Heng 48V20Ah LiFePO4 电池包，目标市场美国。
已知它会触发锂电运输、危险品文件、美国进口税费和越南/实际出口国要求核验；UN38.3、SDS、包装方式、出口申报国和起运港如果资料不足，会保留待确认。
我会表格化整理客观信息，不写“可普通货运输”“最终税率就是 X%”或“建议进入美国市场”。
```

### 13.2 UNIQLO 纺织样本

```text
我理解你要做的是：产品出海市场分析。
本轮对象：UNIQLO Men's Corduroy Overshirt 470177，Production: China，目标市场美国。
这会触发纺织成分、护理标签、原产地标识、候选 HTSUS、出口国要求和常见运输组织方式核验；实物标签、BOM、克重、起运港和最终归类不足时会列为待确认。
我会整理客观参考，不把网页标签当实物标签合规，也不生成客户名单。
```
