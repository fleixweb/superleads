# 产品出海市场分析：输出矩阵与端到端验收设计

本文件定义首批两个真实样本的“应该怎么展示”和“怎样算通过验收”。它不是市场研究结论，也不是代码实现方案。

## 1. 设计目标

| 目标 | 说明 |
|---|---|
| 说人话 | 用户第一眼能看懂：已确定什么、不能确定什么、下一步要补什么 |
| 表格优先 | 对话中用 Markdown 表格、分组标题、要点列表；完整交付可导出 XLSX/CSV |
| 条件清楚 | 每个税率、法规、运输路径和趋势信号都要绑定适用条件 |
| 不替用户判断 | 不输出“值得进入”“建议进入”“市场潜力高”“最佳运输方式” |
| 防幻觉 | 搜索摘要、外部模型整理、前序 Skill 摘要都不能直接变成事实 |

## 2. 对话交付的推荐顺序

用户在 ChatGPT app / Codex 中看到的第一版报告，应按以下顺序展示。每张表最多 6 列。

| 顺序 | 模块 | 这部分回答什么 | 展示方式 |
|---:|---|---|---|
| 1 | 先看结论边界 | 哪些信息已核实，哪些不能下结论 | 3 行以内要点 + 总览表 |
| 2 | 产品档案与触发项 | 产品到底是什么，会触发哪些核验路径 | Markdown 表格 |
| 3 | 贸易前提 | 原产国、出口申报国、起运地、目的国是否分清 | Markdown 表格 |
| 4 | 市场与价格参考 | Google Trends、公开报告、线上价格是否有可读来源 | 状态矩阵；无数据时写未执行/待补充 |
| 5 | 准入与合规 | 目的国法规、认证/测试/注册、包装、标签、质量要求；目标国要求与用户材料状态分列 | 条件矩阵 |
| 6 | 进口税费 | 候选 HS/HTS、基础税、附加税、计算口径 | 税费拆分表 |
| 7 | 出口国要求 | 出口申报国的商检、管制、证书、检疫等 | 待确认矩阵 |
| 8 | 物流与申报节点 | 海运、拼箱、空运、快递等可怎么列、缺什么 | 运输方式矩阵 + 可选 Mermaid |
| 9 | 近期外部因素 | 政治、假期、战争、灾害、金融等是否有来源 | 时间线/状态表 |
| 10 | 来源与待办 | 用户下一步要补哪些材料，来源在哪里 | 来源表 + 待确认清单 |

## 3. XLSX / CSV 工作表合同

完整导出至少包含 12 张表。表名应尽量“国人看得懂”，避免内部对象名。

| 工作表 | 主要字段 | 必须出现的状态 | 禁止内容 |
|---|---|---|---|
| 市场事实总览 | 产品、目的国、原产证据、关键缺口、报告日期 | 已核实 / 候选 / 待确认 | 市场进入建议 |
| 产品档案与触发项 | 属性、当前值、状态、触发的核验路径、来源 | 已核实 / 派生计算 / 待技术资料确认 | 猜测材质、认证或危险品等级 |
| 长期需求与搜索趋势 | 关键词、国家、时间范围、指标口径、趋势状态 | 已核实 / 未执行 / 数据不足 | 把搜索兴趣写成销量 |
| 公开市场资料与行业信息 | 来源名称、指标、时间、可见内容、限制 | 初步参考 / 来源受限 | 付费报告摘要数字当事实 |
| 线上市场与价格参考 | 平台、规格、价格、币种、税/运费状态、日期 | 初步参考 / 不适用 / 未执行 | 真实成交价推断 |
| 季节、节日与销售窗口 | 节点、日期、适用品类、来源、影响口径 | 已核实 / 初步参考 / 不适用 | 主观旺季判断 |
| 产品准入与合规要求 | 要求、适用条件、来源、目标国要求状态、用户材料状态、缺口 | 已核实 / 待技术资料确认 / 待专业确认 | 无条件写“已合规”；用户没证书=不需要认证 |
| 进口税费 | 候选税号、税种、税率、适用条件、计算税基、缺口 | 候选 / 待专业确认 | 单一“最终税率” |
| 出口国要求 | 出口申报国、要求、适用条件、证据、缺口 | 待确认 / 已核实 / 不适用 | 把原产国等同出口申报国 |
| 运输方式、路线、港口与申报节点 | 方式、起运/目的节点、适用条件、时效口径、缺口 | 待确认 / 初步参考 / 来源受限 | 承诺船期或最佳路线 |
| 近期外部因素 | 因素、地区、时间、影响对象、来源、状态 | 已核实 / 初步参考 / 未执行 | 无日期“最新行情” |
| 信息来源与待确认事项 | 来源名称、URL/文件、观察日期、支持字段、待补材料 | 已打开 / 已抽取 / 待补充 | 本地路径、哈希、内部规则 ID |

## 4. 状态词与人话解释

| 状态 | 给用户看的解释 | 适用场景 |
|---|---|---|
| 已核实 | 已看到公开网页、文件或官方来源，能支持这个字段 | 产品参数、页面原产、官方税则标题 |
| 派生计算 | 用已核实数字算出来，不是来源原文 | Wh = V × Ah |
| 候选 | 可以作为下一步核验方向，不能当最终结果 | 候选 HS/HTS、候选 UN 编号 |
| 初步参考 | 有公开信号，但口径有限或不是主管来源 | 平台价格、公开报告摘要 |
| 待技术资料确认 | 需要产品文件、SDS、UN38.3、BOM、标签图等 | 锂电、纺织实物标签、辅料 |
| 待专业确认 | 需要报关、法规、认证、承运人或主管机关判断 | 最终归类、税费、认证适用性 |
| 来源受限 | 找到线索但无法读取完整内容 | 付费报告、JS/登录限制 |
| 未执行 | 本轮没有做这类数据采集 | Google Trends、价格样本、节假日 |
| 不适用 | 已确认该项不适用于本产品/路径 | 非食品接触、非农产品等 |

## 5. 样本 A 验收：Xing Heng 48V20Ah LiFePO4 电池包

### 5.1 必须出现在“产品档案与触发项”里的内容

| 字段 | 期望显示 | 状态 | 验收重点 |
|---|---|---|---|
| 产品版本 | Xing Heng `48V20Ah` | 已核实 | 不能只写“锂电池” |
| Design No. | `BAT001.02` | 已核实 | 型号与证书/测试报告一致 |
| 电池体系 | Lithium-ion / LiFePO4 | 已核实 | 同时触发锂电与危险品核验 |
| 电压/容量 | 48 V / 20 Ah | 已核实 | 不得改写为其它规格 |
| Wh | 960 Wh = 48 × 20 | 派生计算 | 必须写明非厂商单独标注 |
| UN38.3 | 公开页未证实 | 待技术资料确认 | 不得把 QCVN 91 文件当 UN38.3 |
| SDS | 公开页未见 | 待技术资料确认 | 不得写“无需 SDS” |
| 包装方式 | 未公开 | 待技术资料确认 | 不得判断可空运/快递/拼箱 |

### 5.2 必须出现在“准入/运输/税费”里的内容

| 模块 | 必须展示 | 状态 | 禁止输出 |
|---|---|---|---|
| 锂电运输 | 49 CFR §173.185、UN38.3 test summary、100Wh 小型锂电限值 | 已核实 + 待技术资料确认 | “可按普通货运输” |
| UN 编号 | 单独电池包候选 UN3480；随设备/装入设备按 UN3481 判断 | 候选 | 无条件固定 UN 编号 |
| 候选 HTSUS | `8507.60.00` Lithium-ion batteries；基础税率和 Chapter 99 脚注分开 | 候选 | “最终税率为 3.4%” |
| 贸易地理 | 制造/装配地为河内 Soc Son；实际出口申报国和起运港未公开 | 已核实 + 待确认 | 默认填海防港或越南出口 |
| 运输方式 | FCL/LCL/空运/快递均以锂电文件、包装、承运条件为前提 | 待确认 | 推荐最佳方式或承诺时效 |

## 6. 样本 B 验收：UNIQLO Men's Corduroy Overshirt `470177`

### 6.1 必须出现在“产品档案与触发项”里的内容

| 字段 | 期望显示 | 状态 | 验收重点 |
|---|---|---|---|
| 产品版本 | Men's Corduroy Overshirt，Product ID `470177` | 已核实 | 不能泛化为“纺织品” |
| 原产/Production | China | 已核实 | 仍需区分制造工厂和起运港未知 |
| 成分 | Body 100% Cotton / Trim 100% Cotton | 已核实 | 不得推出辅料全为棉 |
| 织物 | 8-wale corduroy made with 100% cotton | 已核实 | 最终归类仍待专业确认 |
| RN / 洗护 | RN 139864；Machine wash cold, gentle cycle, Dry clean | 已核实 | 网页文案不等于实物标签已核验 |
| 单件重量/克重 | 未公开 | 待技术资料确认 | 不得猜克重 |
| 辅料/BOM | 未公开 | 待技术资料确认 | 不得认证“无动物材料” |

### 6.2 必须出现在“准入/标签/税费”里的内容

| 模块 | 必须展示 | 状态 | 禁止输出 |
|---|---|---|---|
| 纺织标签 | FTC 纤维成分、原产地、RN/企业识别路径 | 已核实 + 待实物核验 | “标签已完全合规” |
| 护理标签 | FTC Care Labeling Rule 路径，页面已有洗护说明 | 已核实 + 待实物核验 | 把网页文案当水洗标照片 |
| 原产标识 | CBP country of origin marking 路径 | 已核实 + 待专业确认 | 忽略实物标识要求 |
| 候选 HTSUS | `6205.20.20` 作为男式/男童非针织棉制衬衫路径候选 | 候选 | “一定归 6205.20.20” |
| 贸易救济 | Chapter 99 脚注作为核验项 | 待专业确认 | 不绑定最终 10 位税号就算附加税 |
| 运输方式 | FCL/LCL/空运/快递均可作为组织方式矩阵候选 | 初步参考/待确认 | 推荐最佳运输方式 |

## 7. “未执行”也要显式展示

首批验收并不要求已经完成 Google Trends、线上价格、节假日和近期外部因素采集；但报告不能空白或编造。

| 模块 | 样本 A 当前验收输出 | 样本 B 当前验收输出 |
|---|---|---|
| Google Trends | 未执行；需要关键词、国家、时间范围和数据导出方式 | 未执行；需要关键词、国家、时间范围和数据导出方式 |
| 公开市场报告 | 未执行；不得用搜索摘要补数字 | 未执行；不得用搜索摘要补数字 |
| 线上价格参考 | 未执行；锂电规格、运输和合规条件会影响价格可比性 | 未执行；需区分零售价、促销、尺码、颜色、税运费 |
| 节日/季节 | 未执行；不能默认礼品属性 | 未执行；可后续按服装季节和美国节日检索 |
| 近期外部因素 | 未执行；没有来源不称“最新” | 未执行；没有来源不称“最新” |

## 8. 端到端验收断言

### 8.1 结构断言

| 编号 | 断言 |
|---|---|
| S-01 | 对话报告必须优先表格化，不能是一大段散文 |
| S-02 | 用户可见表格单表不超过 6 列；复杂信息拆成多表 |
| S-03 | XLSX/CSV 至少包含本文件第 3 节的 12 张表或等价中文表名 |
| S-04 | 每条事实或候选信息必须有状态；不能用空白代替未知 |
| S-05 | 来源表不得暴露本地路径、哈希、内部规则 ID 或内部对象名 |

### 8.2 证据断言

| 编号 | 断言 |
|---|---|
| E-01 | 外部模型/搜索摘要只能作为候选线索，不能作为已核实事实 |
| E-02 | 产品页、PDF、官方法规、官方税则必须区分来源类型和观察日期 |
| E-03 | 原产地证据等级必须显示；不能把工厂地址、生产声明、COO 混为一类 |
| E-04 | 候选税号必须标“候选/待专业确认”；不能写成最终归类 |
| E-05 | 法规/税费/管制若写“最新”，必须有有效日期、来源日期或复核日期 |

### 8.3 负向断言

| 编号 | 不得出现的输出 |
|---|---|
| N-01 | 值得进入、建议进入、市场潜力高、推荐开发、最佳运输方式 |
| N-02 | Xing Heng 已具备 UN38.3、无需 SDS、可按普通货运输 |
| N-03 | Xing Heng 最终税率就是 3.4% 或固定适用 `8507.60.00` |
| N-04 | UNIQLO 标签已完全合规、辅料无动物材料、一定归 `6205.20.20` |
| N-05 | 把未执行的 Google Trends、价格、节假日、外部因素写成结论 |

## 9. 下一步实现切片建议

| 切片 | 目标 | 完成标准 |
|---|---|---|
| Slice 1：静态样本报告模板 | 不联网，用已验证字段生成两份 Markdown 样例 | 两个样本均通过结构、状态、负向断言 |
| Slice 2：XLSX/CSV 表头与状态枚举 | 先导出空矩阵/样本矩阵 | 12 张表齐全，未知项不丢失 |
| Slice 3：证据边界校验 | 检查候选税号、UN38.3/SDS、实物标签等禁止升级 | 负向断言全部可测 |
| Slice 4：Skill 分工互证流程 | 明确六个 Skill 的证据卡、交接、互证、打回和门禁 | 前序摘要不能变事实，冲突/缺口/未执行能保留到最终矩阵 |
| Slice 5：数据模型与 eval 夹具设计 | 把证据卡、状态流转和禁止升级断言整理成可实现结构 | 仍可先不写代码，但实现边界清楚 |
| Slice 6：实现前执行计划 | 拆分 schema、validator、fixture、audit、export、eval 集成等最小代码切片 | 明确第一轮只做防错闭环，不接真实市场数据 |
| Slice 7：Skill 文案与用户入口设计 | 明确用户怎么触发、系统怎么追问、怎么避免误路由 | 市场分析不变客户名单，不做价值判断 |
| Slice 8：真实来源采集策略 | 明确趋势、价格、法规、税费、出口、物流和外部因素的来源优先级与降级策略 | 每条未来事实都能追到打开来源、日期和状态 |
| Slice 9：Source Pack 字段合同 | 明确 Source Pack、SourceEntry、QueryTemplate、ObservationRequirement 和 PackRouteRule 的字段与边界 | Pack 只是来源入口目录，不能直接变事实 |
| Slice 10：Source Pack 种子样例设计 | 先用美国/中国/越南和两个样本做最小来源目录样例，不写真实事实结论 | 每个样例只含入口和边界，不含税率、认证结论、物流承诺或价格结论 |
| Slice 11：端到端运行剧本 | 用一条锂电和一条纺织样本串起 Brief -> Pack -> Query Plan -> Observation -> EvidenceCard -> MatrixRow 的人工运行剧本 | 不联网也能验证状态流转、打回、降级和用户可见表达 |
| Slice 12：MVP 收口与实现前冻结 | 汇总 Slice 1-11，冻结第一轮代码只做什么、不做什么、验收命令和提交边界 | 可以安全进入 Code Slice A-C，且不破坏现有客户开发/背调链路 |

当前产品规格已完成 MVP 收口。下一步二选一：先提交 Slice 1-12 文档，或在用户明确后开始 Code Slice A-C。
