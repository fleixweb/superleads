# 产品出海市场分析：XLSX / CSV 工作簿合同（Slice 2）

本文件冻结第一版工作簿表结构、字段顺序、状态枚举和空值保留规则。它不定义代码实现，也不新增市场事实。

## 1. Slice 2 边界

| 项目 | 本轮决定 |
|---|---|
| 交付对象 | `产品出海市场分析` 的 XLSX / CSV 信息矩阵 |
| 首批样本 | Xing Heng `48V20Ah` LiFePO4 电池包；UNIQLO Men's Corduroy Overshirt `470177` |
| 本轮不做 | 不联网、不抓 Google Trends、不新增法规来源、不生成真实 XLSX 文件、不改现有导出器 |
| 本轮产物 | 表名、字段顺序、状态枚举、空值规则、最小样例矩阵 |

## 2. 工作簿总规则

| 规则 | 说明 |
|---|---|
| 表名说人话 | 使用中文业务表名，避免内部对象名、规则 ID、graph、claim、observation 等词 |
| 一事一行 | 一个税种、一个运输方式、一个合规要求、一个来源支持点尽量独立成行 |
| 状态必填 | 每一行都必须有 `状态`，不能用空白代表未知 |
| 条件必填 | 税费、法规、运输、趋势、价格必须有适用条件或缺口说明 |
| 日期必填 | 有来源日期写来源日期；只有本轮查看写观察日期；都没有写 `日期未见` |
| 来源可追溯 | 用户可见来源只放公开 URL、文件名、来源名称或“用户待提供”，不放本地路径、哈希、内部 ID |
| 不自动合并地理 | 卖方所在国、出口申报国、原产国、实际起运地、目的国、目的港分开记录 |
| 不自动升级结论 | 候选 HTS、证书、测试报告、网页标签信息都不能自动升级为最终结论 |

## 3. 状态枚举

| 状态 | 人话解释 | 是否可支持确定结论 |
|---|---|---|
| 已核实 | 已打开公开网页、抽取文件或读取官方来源，能支持该字段 | 仅支持该字段本身 |
| 派生计算 | 用已核实数字按明示公式算出 | 仅支持该计算值，不能替代原始文件 |
| 候选 | 可作为下一步核验方向 | 否 |
| 初步参考 | 有公开信号，但口径有限或不是主管来源 | 否 |
| 待业务确认 | 需要用户、订单或供应链文件确认 | 否 |
| 待技术资料确认 | 需要 SDS、UN38.3、BOM、标签、规格书等技术资料 | 否 |
| 待实物核验 | 需要实物照片、标签、样品或检测 | 否 |
| 待专业确认 | 需要报关、认证、承运人、律师或主管机关确认 | 否 |
| 来源受限 | 有线索但无法读取完整来源 | 否 |
| 未执行 | 本轮没有做该项采集 | 否 |
| 不适用 | 已确认该项不适用于本产品或路径 | 可作为排除说明 |
| 未提供 | 用户或公开来源未给出 | 否 |
| 有冲突待复核 | 来源之间不一致，需要复核 | 否 |

## 3.1 原产地证明 / COO 专用状态

COO / proof of origin 在工作簿里必须拆成两类状态，不能只写成“用户未提供”。

| 状态组 | 字段 | 允许值 | 说明 |
|---|---|---|---|
| 目标国规则状态 | `原产地证明要求结论` | `required` / `conditionally_required` / `normally_not_required` / `not_applicable` / `unable_to_verify` | 回答目标国规则是否要求、什么条件下要求 |
| 用户材料状态 | `用户材料状态` | `user_provided_valid_for_scope` / `user_provided_needs_review` / `user_not_provided_but_required` / `user_not_provided_and_not_required_for_current_scenario` / `user_material_status_unknown` | 回答用户当前是否准备了适用文件 |

规则：目标国规则状态必须基于目的国官方/权威来源；用户材料状态必须基于用户文件或明确未提供状态。两列不得互相推导。

## 4. 空值与 CSV 规则

| 场景 | 写法 | 禁止写法 |
|---|---|---|
| 用户没提供 | `未提供`，并在 `缺口/下一步` 写需要什么 | 空白、`N/A`、猜测值 |
| 用户没提供 COO | `用户材料状态=user_not_provided_but_required` 或 `user_material_status_unknown`，目标国规则另列 | 写成“目标国不需要 COO”或“是否需要待用户提供后判断” |
| 本轮没采集 | `未执行` | 编一个行业常识结论 |
| 不适用 | `不适用` + 简短依据 | 空白 |
| 日期未知 | `日期未见` | 自动填今天当来源日期 |
| 数字未知 | `未提供` | `0` |
| 价格未知 | `未执行` 或 `未提供` | `$0`、`待询价` 当事实 |
| 多来源支持 | 优先多行；CSV 中可用 `；` 分隔 | 把多个来源混成一条无定位摘要 |
| 公式 | 用文本写公式，如 `960 Wh = 48 V × 20 Ah` | 在 CSV 中依赖 Excel 公式 |
| URL | 只放公开 HTTP(S) URL | 本地路径、带 token 的 URL、内部哈希 |

#### 5.7.1 `origin_proof_requirement` 专门行

`产品准入与合规要求` 中必须允许一类专门行：`origin_proof_requirement`。这类行不是问用户有没有 COO，而是先展示目标国规则。

| 字段 | 必填 | 说明 |
|---|---|---|
| 样本ID | 是 | 与总览一致 |
| 要求类别 | 是 | 固定可写 `原产地证明 / COO` |
| 要求名称 | 是 | `origin_proof_requirement` 或人话名称 |
| 目的国/地区 | 是 | 规则属于目标国/进口地区 |
| 原产国/出口国 | 是 | 未知也要写待确认，不能留空 |
| 候选 HS/HTS | 是 | 候选或待专业确认 |
| 原产地证明要求结论 | 是 | required / conditionally_required / normally_not_required / not_applicable / unable_to_verify |
| 触发条件 | 是 | 普通进口、优惠税率、FTA、贸易救济、配额、制裁、进口商/信用证等 |
| 可接受文件 | 是 | COO、origin declaration、invoice statement 等，按官方来源写 |
| 用户材料状态 | 是 | 已提供/未提供/需复核/未知，必须与目标国规则分列 |
| 当前证据 | 是 | 官方/权威来源 + 用户文件状态 |
| 状态 | 是 | 使用工作簿状态枚举 |
| 官方/优先来源 | 是 | 官方/权威来源名称、URL/文件、观察日期 |
| 待补材料 | 是 | 如 COO、发票声明、签发机构资料、订单文件等 |
| 禁止升级 | 是 | 不等同海关最终裁定；不把 marking 当 COO；不把优惠 proof 泛化所有进口 |

## 6. 两个样本的最小行数要求

|---|---:|---:|---|

| 长期需求与搜索趋势 | ≥1 | ≥1 | 即使未执行也要有状态行 |

| 线上市场与价格参考 | ≥1 | ≥1 | 未执行行保留 |

## 7. 验收断言

| 编号 | 断言 |
|---|---|
| W-01 | 12 张表名必须存在，顺序与本文件一致，或有等价中文表名映射 |
| W-02 | 每张表必须包含 `样本ID` 或可回连样本的字段 |
| W-03 | 每张表必须包含 `状态` 或等价状态字段 |
| W-04 | 未知数字不能填 0，未知文本不能留空 |
| W-05 | 候选 HTSUS、UN 编号、运输方式不能在表内升级为最终结论 |
| W-06 | 未执行的趋势、价格、市场报告、节日、外部因素必须保留行，不得删除 |
| W-07 | 来源表不得出现本地路径、哈希、内部规则 ID、内部对象名 |
| W-08 | Xing Heng 必须保留 UN38.3、SDS、包装、起运港缺口 |
| W-09 | UNIQLO 必须保留实物标签、辅料/BOM、克重/重量、起运港缺口 |
| W-10 | 工作簿不得出现“建议进入”“最终税率就是”“最佳运输方式”等价值判断或无条件结论 |
| W-11 | COO / 原产地证明必须拆成“目标国要求状态”和“用户材料状态”，不得互相推导 |
| W-12 | Country of Origin Marking / Made in / Production 不得写成 COO 文件要求；优惠税率 proof of origin 不得泛化为所有普通进口必需 |
