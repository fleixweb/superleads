# 产品出海市场分析 Slice 13：目标国原产地证明 / COO 要求判断规则

一句话目标：**把 COO / 原产地证书从“用户有没有给的材料缺口”，升级为产品出海市场分析必须主动判断的目标国合规条件；同时仍把用户当前是否具备该文件作为单独的执行准备状态展示。**

## 1. 背景纠偏

此前设计已经正确区分了：

- 工厂地址 / 品牌页 / Production 声明不能等同海关最终原产地；
- COO、发票、提单、装箱单等订单文件不能泛化到所有 SKU；
- 用户提供文件不能替代主管机关最终裁定。

但现有表达仍容易让系统把 COO 处理成：

> 用户有没有提供原产地证书。

这不够。真实外贸业务里，产品市场分析要先回答：

> 该产品往目标国家/地区销售时，目标国家/地区官方规则是否要求某种原产地证明？什么条件下要求？可接受哪类文件？没有会影响什么？

用户当前是否已经有 COO，只能作为第二层“资料准备状态”，不能替代法规判断。

## 2. 核心决定

| 编号 | 决定 | 说明 |
|---|---|---|
| D13-01 | COO / 原产地证明要求是目的国准入/清关/税费规则的一部分 | 不再只放在“用户资料缺口”里 |
| D13-02 | “目标国是否需要”与“用户是否已提供”必须分成两列 | 前者是法规要求，后者是执行准备状态 |
| D13-03 | 必须基于产品、目标国、原产国/出口国、候选 HS 和贸易优惠场景查询 | 不能只凭通用记忆回答 |
| D13-04 | 结论允许是假设性业务分析 | 即使用户没有文件，也要客观告诉他在该目标市场是否需要、何时需要 |
| D13-05 | 是否进入市场仍由用户自行判断 | 系统只讲必要条件、风险口径和权威来源，不做价值主张 |

## 3. 术语边界

| 术语 | 人话解释 | 常见触发场景 | 不能混同 |
|---|---|---|---|
| COO / Certificate of Origin | 原产地证书，通常由授权机构或商会等签发，用来证明货物原产地 | 清关、优惠税率、进口商要求、贸易救济、信用证/合同 | 不能等同 Made in 标签 |
| Proof of Origin | 原产地证明的总称，可能是证书、声明、发票声明等 | 优惠关税、FTA、海关核验 | 不能等同只有纸质 COO |
| Origin Declaration / Statement on Origin | 出口商或授权出口商在发票或商业文件上的原产地声明 | 一些贸易协定、低金额货物、注册出口商制度 | 不能等同所有国家都接受 |
| Country of Origin Marking | 原产国标识，如 Made in China | 商品标签、包装、零售合规 | 不等于 COO 文件 |
| Preferential origin | 优惠原产地，用于申请 FTA/优惠税率 | FTA、GSP、区域协定 | 不等于普通非优惠原产地 |
| Non-preferential origin | 非优惠原产地，用于普通清关、贸易救济、统计等 | 反倾销、配额、制裁、原产地标识 | 不等于一定有优惠税率 |

## 4. 两条线必须拆开

### 4.1 目标国规则线

这是产品出海市场分析必须主动查询并输出的。

| 字段 | 说明 |
|---|---|
| 是否需要原产地证明 | `需要` / `条件性需要` / `通常不要求` / `未能核实` |
| 触发条件 | 普通进口、优惠关税、FTA、反倾销/反补贴、配额、制裁、食品/农产品/纺织/敏感品类、进口商/信用证要求等 |
| 可接受文件 | COO、preferential certificate、origin declaration、invoice declaration、statement on origin、supplier declaration 等 |
| 权威来源 | 目的国海关、官方进口指南、税则、贸易协定文本、原产地规则页面、主管部门公告 |
| 对业务影响 | 影响清关、税率、优惠关税资格、贸易救济适用、标签、进口商收货资料等 |

### 4.2 用户材料线

这是用户当前资料准备状态，不能反推法规要求。

| 字段 | 说明 |
|---|---|
| 用户是否已提供 | 已提供 / 未提供 / 部分提供 / 不适用 / 未询问 |
| 文件可读状态 | 已读取 / 无法读取 / 待用户补传 / 来源受限 |
| 文件核对项 | 文件类型、签发机构、签发日期、出口商、进口商、发票号、产品描述、数量、HS、原产国、适用协定、签章/编号 |
| 文件适用范围 | 订单/批次/SKU/型号/日期，不得泛化 |
| 与法规要求关系 | 满足 / 可能满足 / 不满足 / 不能判断 / 不适用 |

## 5. 输出状态枚举

### 5.1 目标国原产地证明要求状态

| 状态 | 什么时候用 | 用户可见说法 |
|---|---|---|
| `required` | 官方来源明确该场景需要 COO / proof of origin | “该目标市场在当前条件下需要原产地证明。” |
| `conditionally_required` | 只有在申请优惠税率、特定协定、特定品类、贸易救济或进口商/清关场景下需要 | “不是所有场景都必需，但在以下条件下需要。” |
| `normally_not_required` | 官方来源支持普通进口通常不要求独立 COO，但仍可能要求原产地标识或海关可要求证明 | “普通进口通常不要求单独 COO；但仍需满足原产地标识/海关核验等规则。” |
| `not_applicable` | 该产品/场景不适用原产地证明问题 | “本场景暂不适用。” |
| `unable_to_verify` | 没有打开权威来源、来源冲突或条件不足 | “未能用权威来源核实是否需要，不能写需要或不需要。” |

### 5.2 用户材料准备状态

| 状态 | 说明 |
|---|---|
| `user_provided_valid_for_scope` | 用户文件已提供，且在当前订单/产品/目标国条件下初步匹配；仍需专业/海关确认 |
| `user_provided_needs_review` | 用户提供了文件，但缺少签发方、日期、型号、协定、HS 等关键项 |
| `user_not_provided_but_required` | 目标国规则显示需要或条件性需要，但用户当前未提供 |
| `user_not_provided_and_not_required_for_current_scenario` | 当前核验场景通常不要求该文件 |
| `user_material_status_unknown` | 尚未询问或无法读取用户资料 |

## 6. 证据优先级

| 结论类型 | 第一优先来源 | 第二优先来源 | 只能参考 | 不得作为事实 |
|---|---|---|---|---|
| 目标国是否要求 COO / proof of origin | 目的国海关、官方进口指南、官方税则、贸易协定官方文本、原产地规则官方页面 | 商务部/贸易促进机构、官方 Access2Markets 类平台、主管部门 FAQ | 报关行/律所/货代公开文章 | 搜索摘要、模型记忆、无来源博客 |
| 可接受文件类型 | 目的国海关、贸易协定文本、官方原产地规则 | 官方贸易门户、商会/签证机构官方说明 | 行业解释文章 | 供应商口头说法 |
| 用户提供文件是否匹配 | 用户文件原文、文件截图/PDF、发票/合同/装箱单/提单 | 供应商确认邮件 | 用户口头描述 | 文件名或聊天摘要 |

## 7. 必须查询的判断维度

| 维度 | 为什么重要 |
|---|---|
| 目标国家/地区 | 不同国家对普通清关、优惠原产地、标签和贸易救济要求不同 |
| 原产国 / 制造来源 | 影响 FTA、反倾销、制裁、贸易救济和标签要求 |
| 出口申报国 / 起运国 | 不等同原产国，但影响出口侧文件和物流文件 |
| 候选 HS/HTS | 很多原产地证明、优惠税率和贸易救济按税号触发 |
| 产品属性 | 食品、农产品、纺织、钢材、化学品、电池、两用物项等可能有特殊要求 |
| 贸易优惠诉求 | 是否申请 FTA/GSP/优惠税率，决定 proof of origin 的必要性 |
| 进口商/合同/信用证要求 | 即使法规不强制，商业文件也可能要求 COO |
| 报关日期 / 生效日期 | 规则可能变化，必须记录查询日期和法规生效口径 |

## 8. 用户可见矩阵字段

新增或修正“产品准入与合规要求 / 进口税费 / 信息来源与待确认事项”中的原产地证明行。

| 字段 | 示例 |
|---|---|
| 样本ID | XH-48V20AH-US |
| 目的国/地区 | United States |
| 原产国/制造来源 | Vietnam 公开来源线索，正式原产地按文件/规则确认 |
| 候选 HS/HTS | 8507.60.00，候选 |
| 原产地证明要求结论 | 条件性需要 |
| 触发条件 | 申请优惠税率、海关要求证明原产地、贸易救济/特殊监管场景 |
| 可接受文件 | COO / origin declaration / invoice statement，按官方规则确认 |
| 用户当前材料状态 | 用户未提供 COO |
| 对业务影响 | 若触发该场景，需提前准备；否则可能无法享受优惠税率或被要求补证 |
| 权威来源 | 目的国海关/官方贸易门户/协定文本，含 URL 和观察日期 |
| 限制说明 | 不替用户判断是否做；不等同海关最终裁定 |

## 9. 人话表达模板

### 9.1 需要

```text
按已打开的目标国官方来源，当前产品/税号/原产地条件下，进口时需要提供原产地证明。用户当前未提供该文件，因此这不是“不能分析”，而是“必要材料未准备”。如果继续推进，需要向签证机构、供应商或出口方准备对应文件，并让报关/进口专业方确认格式和适用范围。
```

### 9.2 条件性需要

```text
该目标市场不是所有进口场景都强制单独 COO，但在申请优惠关税、使用贸易协定、触发贸易救济/配额/敏感品类监管，或海关要求证明原产地时，需要提供 proof of origin。用户当前未提供该文件，不影响我们列出规则；但如果业务计划走上述场景，需要提前准备。
```

### 9.3 通常不要求

```text
按当前已打开的官方来源，普通进口场景通常不要求单独 COO；但这不等于没有原产地要求。仍可能需要原产国标识、发票/报关资料中的原产地信息，并且海关有权要求证明。若申请优惠税率或合同/信用证要求，则要另行准备原产地证明。
```

### 9.4 未能核实

```text
本轮没有打开足够权威的目标国来源，不能写需要，也不能写不需要。当前只保留为“未能核实”，并列出需要查询的官方入口。
```

## 10. 禁止升级 / 禁止误导

| 错误表达 | 为什么错 | 应改成 |
|---|---|---|
| 用户没提供 COO，所以目标国是否需要待确认 | 混淆用户材料状态与法规要求 | 先查目标国规则；用户未提供只写材料状态 |
| 用户没提供 COO，所以不需要 COO | 无证据反推 | 未提供 ≠ 不需要 |
| 目标国需要原产地标识，所以一定需要 COO | 混淆 marking 与 certificate | 区分 Made in 标识和原产地证明文件 |
| 申请优惠税率需要 proof of origin，所以所有普通进口都要 COO | 混淆优惠与普通清关 | 写“条件性需要” |
| 产品页写 Made in Vietnam，所以满足目标国 COO 要求 | 公开页面不是目标国可接受原产地证明 | 只能作制造来源线索 |
| 有 COO，所以最终原产地已由海关裁定 | 用户贸易文件不是主管机关裁定 | 订单/批次文件支持，仍需专业/海关确认 |
| COO 需求用模型记忆回答 | 法规规则时效性高 | 必须打开官方/权威来源并记录日期 |

## 11. Skill 分工修正

| Skill | 新增责任 | 必须避免 |
|---|---|---|
| Skill A Brief 与属性识别 | 记录原产国线索、出口申报国、目标国、候选 HS 缺口和用户是否提供贸易文件 | 不把用户未提供写成目标国不需要 |
| Skill C 目的国准入/税费 | 主动查询目标国 COO / proof of origin 是否需要、何时需要、接受文件类型和官方来源 | 不把 COO 只作为用户缺口 |
| Skill D 出口国要求 | 查询出口申报国是否有签发/申领原产地证书的出口侧程序或机构要求 | 不把目的国清关要求写成出口国强制要求 |
| Skill E 物流与申报 | 记录 COO 与提单、发票、装箱单、预申报之间的操作节点，但不替代合规判断 | 不把物流文件等同 COO |
| Skill F 交付复核 | 检查“目标国要求”和“用户资料状态”是否分列；检查是否有官方来源 | 不让“用户没有”变成“法规不需要” |

## 12. Source Pack 路由修正

当 Brief 中出现以下任一条件时，应路由到 `origin_proof_requirement` 查询组：

| 触发 | 查询组 |
|---|---|
| 用户问是否需要原产地证书 / COO | 目标国原产地证明要求 |
| 目标国 + 原产国 + 候选 HS 已知或部分已知 | 目标国 proof of origin / rules of origin |
| 用户希望计算关税、FTA、优惠税率 | preferential origin / proof of origin |
| 产品属于纺织、农产品、食品、钢材、化学品、电池、受贸易救济关注品类 | non-preferential origin / trade remedy origin proof |
| 用户上传 COO、发票、提单、装箱单 | 用户材料匹配与适用范围核对 |

## 13. 与原产地证据等级的关系

原产地证据等级仍保留，但用途要重新定位：

| 对象 | 回答什么问题 |
|---|---|
| 目标国原产地证明要求 | “目标国规则是否要求这个文件？” |
| 原产地证据等级 L0-L4 | “我们手上的材料能证明到什么程度？” |
| 用户材料准备状态 | “用户现在有没有准备符合该场景的文件？” |
| 专业/海关确认状态 | “这个判断能不能作为正式报关结论？” |

这四个对象不能互相替代。
